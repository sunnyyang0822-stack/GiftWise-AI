第四屏 · 常见问题

你可能想问的。

答不上来的问题，我们不会写得像答得上。下面是当前实现里确定的部分，以及还没有做的部分。

这是什么？能帮我做什么？

它是一个送礼决策助手：你说清关系、场合、预算和准备时间，它给出三个方向不同的礼物思路，每个思路都带理由、依据和「仍未知」的部分，再由独立规则检查预算、时间与禁忌。它不是商品搜索，也不替你下单。

要花钱吗？要注册吗？

不用注册，也不用填真实姓名。当前是演示版本：页面上出现的所有价格都是估算（含礼物、包装、贺卡、装饰与配送），没有真实商品价格、库存或物流数据；一切都只是估算，不是承诺。

为什么只给三个方案？

三个方向不同的方案比较好比较，也不容易变成一屏挑花眼的清单。就三个，不再追加——避免把「想清楚」变成「再刷一刷」。

我不知道 TA 喜欢什么，还能用吗？

能。兴趣可以整组跳过，跳过就等于未知；系统不会按性别、年龄或职业替你猜。只有你选「明确知道」的才算事实，「只是猜测」会单独标成推断，和事实分开写。

选完之后会发生什么？

只有你明确选定某个通过检查的方案之后，才会按固定顺序生成风格配色、包装材料与步骤、贺卡正文与装饰、赠送时机与话术，并做一次增量复核（总费用、准备时间、禁忌）。这部分当前是目标设计，展示的是模拟结构。

页面上为什么写着「模拟数据」？

因为接入层还没有接入真实模型（未配置模型凭证）：三个方案与四段呈现都来自内置的固定模拟数据，不是模型真实输出。而独立规则校验、选择门槛和修订计数是真实实现，可以真实拦住不合格的方案。

我的输入会被怎么处理？

只在本次会话内使用：运行记录留在接入层进程的内存里，服务重启即失效，不写入数据库；记录里不含密钥、令牌或用户原文。页面不加载任何第三方脚本、字体或 CDN。完整说明见第六屏的隐私条款。

对方一定会喜欢吗？

不会承诺。我们能做的是让礼物更贴合你们的关系、场合和边界；最后是否合适，仍然由你和对方真实的相处决定。这也是为什么页面上一直写着「未核实」。

第六屏 · 工作原理与隐私

它是怎么算出来的，
你的话去了哪里。

两栏都是可以自己核对的：左边是流程与判定顺序，右边是数据边界。没有写在这里的能力，就是还没有做。

工作原理

  1. 先把需求整理成确定的结构

    关系、场合、预算上限、可用天数与硬约束先变成机器能校验的字段；不合法的输入会在提交前就被中文说明拦住，不静默补默认值。

  2. 再生成三个不同的思路

    三个方案方向不同，各自带理由、事实引用、模型推断与「仍未知」，并且明确标出哪些只是估算。

  3. 然后用独立规则检查

    预算、准备时间与禁忌由独立代码校验，不是模型自述「我通过了」；没通过的方案会被标成不可选择，也不会被自动替换成别的方案。

  4. 需要时只自动修订一次

    推荐与呈现两个阶段合计最多一次自动业务修订；额度由服务端持有，浏览器不能提交或篡改，用完后如实报失败。

  5. 你选择之后才生成呈现

    选定之后才按顺序生成风格配色、包装、贺卡装饰与赠送方式，并做增量复核：总费用不超过预算、准备时间不超过可用天数、禁忌仍然不出现。

隐私条款（当前实现）

  • 不收集真实姓名、手机号或邮箱，也不要求注册。唯一的自由文本是「补充说明」，可以不填；页面也不要求上传任何照片或文件。
  • 你的输入只在本次会话里、在这个接入层进程内使用。运行记录保存在内存中，服务重启即失效，不写入数据库，也不做长期留存。
  • 运行记录里不含密钥、令牌或用户原文；页面与仓库都不保存任何真实凭证，密钥只可能放在可信服务端。
  • 页面不加载任何第三方脚本、字体或 CDN：全部资源来自本站，可在浏览器网络面板核对（当前为 0 个外部请求、0 个远程字体）。
  • 当前接入层未接入真实模型（没有配置模型凭证），你的输入不会被发送给任何模型服务；页面常驻的「模拟数据」标识说明的就是这件事。
  • 价格、库存与送达一律未核实（not_verified）：所有费用与准备时间只能读作估算。准备天数表示可用准备时间，不是送达承诺。
  • 公开内容只使用虚构人物与脱敏数据；演示里出现的请求都是构造出来的，不对应任何真实收礼人。

这份说明只描述当前可核对的实现，不构成对未来版本的承诺；未来若接入真实模型，数据边界会随之更新并在此处说明。
