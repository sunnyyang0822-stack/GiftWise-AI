## 1. 结论摘要

- **推荐默认**：路线 A（本机裸跑）保底现场 Demo，**同时**路线 C（UCloud UHost + 容器）作为"云原生"证据来源；
  若 UCloud 无法在截止前落实，则退化为**路线 B（本机装 Docker 构建）**，用真实构建产物支撑"云原生架构与技术选型"。
- **不建议**引入 Kubernetes：当前是**单个无状态进程 + 确定性纯函数**，没有状态、没有多副本、没有弹性需求，
  K8S 只会增加成本与故障面，且评分规则要求的是"使用合理、能解释取舍"，不是"必须使用"。
- 无论选哪条路线，**现场演示必须真实运行**（评分规则 1.3/四：录屏只能作备用）。

### 安全组最小开放原则（针对路线 C）

- TCP 22：**只允许管理员来源 IP**，不要对全网开放。
- 服务端口（默认 8000）：**只允许演示来源**；演示网络来源 IP 未知 → 见 Q5。
- 不要为了省事开 `0.0.0.0/0`：该 API **无认证、无 TLS**（见 `security-review.md` S-1/S-2/S-3）。
