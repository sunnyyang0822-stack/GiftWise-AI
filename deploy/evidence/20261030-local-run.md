**必须说明的测量条件与局限**：

1. 客户端与服务端在同一台机器、同一个 Python 进程中发起（8 个线程），互相争抢 CPU 与 GIL，
   数字是**下界性质的参考值**，不是真实客户端场景的容量。
2. 服务端 `protocol_version` 是 `HTTP/1.0`（实测），**每个请求都新建 TCP 连接**，
   因此中位数包含 TCP 建连开销。两次运行的中位数相差 10 倍以上（1.33 ms vs 14.96 ms），
   说明该指标对机器当前负载非常敏感（采集时可用内存仅 2.87 GiB）。
3. 并发序列出现单次 505.81 ms 的离群值，未做重试或剔除，如实保留。
4. 未测长连接、未测多机、未测跨网耗时、未测容器内性能。

## 7. 用真实 `curl` 复核 README 中的示例命令

README 里写了几条 `curl` 示例，为免"文档示例没跑过"，用**真实 curl** 在 `127.0.0.1:8000` 上逐条执行
（原始输出：`raw/curl-verify-body.txt`、服务端日志 `raw/curl-verify.txt`）：

```
$ curl -sS -i http://127.0.0.1:8000/healthz
HTTP/1.0 200 OK
Server: GiftWiseValidator/0.1 Python/3.12.12
Date: Fri, 30 Oct 2026 13:30:44 GMT
Content-Type: application/json; charset=utf-8
Content-Length: 135
Cache-Control: no-store

{"status":"ok","service":"giftwise-validator","rules_source_sha256":"4782255bb9c9ab48494382ca712d6b92ade248bf64143406161418b6ae744ca3"}

$ curl -sS -i -X POST http://127.0.0.1:8000/validate -H 'Content-Type: application/json' \
    -d @deploy/evidence/raw/_curl-body.json
HTTP/1.0 200 OK
Content-Length: 367
{"status":"needs_input","all_passed":false,"errors":[{"code":"MISSING_FIELD","path":"request.available_days",…}],…}

$ curl -sS -o /dev/null -w '%{http_code}' -X POST http://127.0.0.1:8000/validate -d '{not json'
status=400

$ curl -sS -o /dev/null -w '%{http_code}' http://127.0.0.1:8000/unknown-path
status=404
```

**顺带发现（真实观察，非推测）**：这次启动**没有**设置 `PYTHONUNBUFFERED`，
服务端日志文件里只剩启动那一行，`log_message` 的访问日志在进程被 `pkill` 时随缓冲区丢失。
`Dockerfile` 里已设置 `PYTHONUNBUFFERED=1`（容器内不会丢），但本机裸跑若不带该变量、
又被强杀，就会丢最后一段日志。这进一步说明阶段 14 应改用带 flush 的 `logging` 模块
（已记入 `../observability-collection.md` 第 1 节）。

## 8. 容器布局等价演练（不是容器运行）

本机无 Docker，退而验证"镜像里那份文件树能不能跑"。两种文件集都用同一条
`CMD python -m deploy.server` 启动：

| 布局 | 文件树 | 启动 | `/healthz` | `/validate` | HEALTHCHECK 等价命令 |
| --- | --- | --- | --- | --- | --- |
| `repo_copy`（= Dockerfile 的 COPY 结果） | `deploy/server.py`、`validator/__init__.py`、`validator/rules.py` | 565.8 ms | **200** | HTTP 200，`status=passed`，`all_passed=true` | exit 0 |
| `upload_minimal`（= 发布脚本实际上传的文件） | `deploy/server.py`、`validator/rules.py` | 577.3 ms | **200** | HTTP 200，`status=passed`，`all_passed=true` | exit 0 |

结论：两种文件集都**不需要** `deploy/__init__.py`（Python 3.3+ 命名空间包即可），
`python -m deploy.server` 与 `from validator.rules import validate` 均可用。

HEALTHCHECK 用的是 8000 端口，演练端口不同，因此把命令里的端口替换为等价端口后执行，
输出文件 0 字节 + exit 0（该命令成功时本就无输出）。
**仍未验证**：镜像构建、基础镜像可用性、`USER giftwise`、容器网络与端口映射。
