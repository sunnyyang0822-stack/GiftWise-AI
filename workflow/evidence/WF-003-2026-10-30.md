### 4.4 第一次真实调用暴露的真实缺陷（含根因与修复）

**症状（真实原文）：** 第 1 次真实运行后，两个用例都以 `INVALID_JSON` 结束、无可选方案：

```json
{"status":"error","all_passed":false,
 "validation":{"status":"error","errors":[{"code":"INVALID_JSON","path":"candidates_json",
 "message":"JSON 无效，可能含重复键、非标准常量或嵌套过深"}]}, "repair_count":1,
 "selectable_candidate_ids":[]}
```

**根因（逐字证据）：** N2 的 `outputs.text` 实际以推理块开头，且被 `max_tokens` 截断：

```text
"text": "<think>
<!--dify-deepseek-reasoning-->We need answer only JSON. Need generate 3 candidates. ... (29.75 s，末尾在句子中途被切断)"
```

N3 收到的 `candidates_json` 因此以 `<think>` 开头 → 无法解析。

**只读查证参数规则**（`GET .../models/parameter-rules?model=deepseek-v4-flash`）后确认：

| 参数 | 类型 | 默认 | 说明（服务端原文摘要） |
| --- | --- | --- | --- |
| `thinking` | boolean | **`true`** | "控制是否启用 DeepSeek 的思考模式，默认启用。" |
| `max_tokens` | int | 4096（v4-flash） | "输出 token 上限，**包含思考内容**，最大 393216。" |
| `top_p` | float | 1 | "**思考模式下**的核采样概率，取值 0.95 至 1.0。" |
| `temperature` | float | 1 | "控制**非思考模式**下的随机性。思考模式下不生效。" |
| `response_format` | string | null | 可选 `text`/`json_object`。 |

**修复（已生效，服务端实读确认）：**

```json
{"temperature": 0.2, "max_tokens": 16384, "top_p": 1, "thinking": false, "response_format": "json_object"}
```

关键点：**`thinking` 默认开启，而 `max_tokens` 把推理算在内** —— 4096 被推理耗尽，正文 JSON 根本没生成完；同时 `<think>` 混入 `text`，而按 `workflow/dify-setup.md` 第 40 行"N2 LLM 原始 text 即 candidates_json；不剥围栏、不自动修 JSON"，下游不会清理它，**必然**得到 `INVALID_JSON`。此外 `frequency_penalty`/`presence_penalty` 不在该模型参数规则内，已移除。

### 4.6 由此发现的产品级问题与提示词修复

**问题：** 禁忌词按**字面**匹配全文，因此模型想表达"避开酒精"时写出的"**不含酒精**"本身就命中了禁忌词"酒"。R1 的真实修订恰好把它改写掉了，R2 的真实修订没有 —— 说明**当前提示词没有把"不要写出禁忌词本身（含否定式）"讲清楚**，行为不稳定。

**修复（在 `workflow/prompts/`，属我的工作范围）：**

- `generate.md` 禁忌那条后新增一条："禁忌词按**字面**匹配所有文本字段。因此不要在 name、description、reason、inferences、unknowns 中写出禁忌词或禁忌标签词本身，**包括"不含X""无X""非X"这类否定式与声明式表述**。需要表达该方向不可用时，直接改为描述所选方向，不要提及被禁止的词。"
- `repair.md` 新增一段：要求修复禁忌违规时**必须删除文本里的禁忌词字面**（"不含酒精"→"无该成分"/"以茶饮替代"），并明确"只改 tags 而保留文本中的禁忌词不算修复"。
