# GiftWise AI

帮助用户从“不知道送什么”走到“知道为什么选、怎么送”的 AI 礼赠决策助手。

**项目状态：开发中。** 当前已完成基础仓库、设计文档和推荐阶段离线校验器。开发自测 322 项、阶段 B 契约套件 260 项及 PM 独立探针 8 项实际通过；套件不代表人员隔离的第三方认证。真实推荐、网站、Dify 礼赠闭环及云部署仍待实现或验证。

## 所有协作 Agent 从这里开始

先阅读 [产品定位 Issue #1](https://github.com/sunnyyang0822-stack/GiftWise-AI/issues/1)，再阅读 [协作规范](AGENTS.md)。产品定位以该 Issue 正文为准，需求和技术文档负责细化实现，避免多处维护不同版本。

## 用户和问题

主要面向初入社会的青年。最高频核心目标是恋人及追求者群体，其次朋友，再次职场上司、亲戚家人等关系；这是产品定位优先级，尚无实际频率统计。他们缺少灵感，也担心不合适的礼物造成尴尬或负面效果。次要用户是重视朋友真实偏好的青少年，以及有一定经验、可能存在职场需求的中年人。以上为当前产品假设，尚未经过市场验证。

## 目标体验

输入对方风格、爱好、职业、关系等已知信息，以及预算、禁忌和时间 → 三个不同的礼物方案与理由 → 独立代码校验 → 必要时一次修订与重检 → 用户选择一个合格方案 → 详细包装、配色、贺卡和赠送方式。

事实、推断、未知信息分开呈现。用户自主选择；不提前生成三份详细包装。包装等新增费用和时间同样受原始约束约束，同一任务跨阶段最多一次自动业务修订。没有商品数据源时，价格、供应和送达均未核实。

网站默认简体中文，导航、按钮、操作提示、状态反馈、错误说明和生成内容均使用中文。GitHub 首页、文档、Issue 和协作说明也以中文为主；技术标识符保留原名。

## 运行离线校验测试

在仓库根目录使用 Python 3.12 运行 `python -m unittest discover -s tests -q`；阶段 B 运行 `python tests/acceptance/stage_b/run_acceptance.py`，会生成新的证据目录。校验接口为 `from validator import validate`，接收两个 JSON 字符串，契约见工作流规范。测试不调用模型或网络。

## 开发与体验

日期以北京时间为准。10 月 29 日完成定位与契约，10 月 30 日四线并行并尽早跑通推荐闭环，10 月 31 日接通用户选择后的赠送指南并做回归，11 月 1 日冻结版本、录屏和排练。确切提交截止时间须向主办方核实。

已有同事生日场景保留为技术回归基线；后续产品体验和主展示优先覆盖恋人及追求对象，其次朋友。追求关系不代表双方已有恋爱关系或双向好感。前端先用标记清楚的模拟数据，不能把页面原型当真实模型闭环。详细分工见开发流程。

如需验证现有模型连接，在 Dify 工作室打开 Giftwise → 测试运行，填虚构关系，检查 LLM 和输出节点。当前提示词要求回复“GiftWise 模型连接成功。”，但提示词存在不等于调用成功。失败时私下检查节点错误和供应商配置，不公开密钥。

## 安全与真实性

不提交密钥、私有地址、真实个人信息和未经审查的导出。前端不保存 Dify 或模型密钥，不信任浏览器提交的 passed 标记。离线校验结果见[阶段 B 报告](docs/test-reports/stage-b/acceptance-2026-10-29.md)和 [PM 验收](docs/pm-reviews/val-001-stage-b-acceptance-2026-10-29.md)；Dify、模型、网站及云端测试仍未执行，证据分开记录。赛题是否强制容器或 Kubernetes、是否允许托管 Dify 与外部模型、云资源和截止时间均待确认，不虚构要求。
