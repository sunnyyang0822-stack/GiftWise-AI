### A2 · 起服务（用备用端口）

```bash

```

- [ ] 服务起来了，端口 = `________`
- [ ] 如果前一晚起的还在跑，启动器应当**复用**它而不是再起一个

### A3 · 三次探活（不同路径，确认不只是首页能开）

```bash
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:<端口>/
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:<端口>/app.js
curl -sS -m 5 http://127.0.0.1:<端口>/api/config | head -c 80
```

- [ ] 三个都是 **200**
- [ ] `/api/config` 返回 JSON（含 `"mode":"mock"`）
- [ ] ⚠️ 若 `/app.js` 是 404：**先看 mtime**，别的 Agent 可能正在写文件 → **强刷一次**再判

### A4 · mock 标识（PM 指定项）

浏览器打开主页面，**肉眼确认**：

- [ ] 顶部有一条 **amber（浅橙）底色**的标识
- [ ] 文字逐字是：**`模拟数据 · 未接真实模型`**
- [ ] **滚动页面后它仍然可见**（sticky）
- [ ] 缩放调到 **125%–150%**（否则 12px 在投影上接近不可读）
- [ ] ⚠️ **口播口径**：这条标识针对的是**候选方案与四段呈现**（那才是模拟数据）；**输入表单和校验是真实代码**。不要说成"整站都是假的"

### A5 · 额度余量（PM 指定项）

- [ ] 打开 Dify 侧用量页（**只读，不要点运行**），核对余量
- [ ] 与前一晚记下的 **13 次 / 38,326 tokens** 对比：

  | 情况 | 处置 |
  |---|---|
  | 余量 **没变** | ✅ 正常，继续 |
  | 余量 **变少了** | ⚠️ 有别人跑过。**重算剩余**，并把决策门槛下调 |
  | 余量 **归零** | 🔴 今天**全程模式 B/C**，不要尝试真跑 |

- [ ] 确认现场**不会**触发真实调用（默认走模式 B）

### A6 · 浏览器缓存（PM 指定项）

- [ ] 打开主页面 → **`Ctrl+Shift+R` 强制刷新一次**
- [ ] 刷新后页面完整（**无白屏、无错位**）
- [ ] 打开开发者工具 Console，确认 **`console_errors` 为空**
- [ ] 若白屏：**先强刷**（本轮已知：别的 Agent 正在写 `web/public/`，读到半截文件会白屏），强刷不行再换端口

> **为什么必须强刷**：本轮实测发现同一份 `web/public/` 会被多个 Agent 同时改写。缓存 + 半截写入是白屏的头号原因。强刷成本 2 秒，收益是避免现场翻车。

### A7 · 缓存与文件新鲜度判定（白屏时用）

如果刷新后**还是**有问题，判断是"暂时性"还是"真问题"：

```bash
node docs/demo/bin/retry-on-404.mjs web/public/app.js
```

- [ ] `file_age_s` **很小**（如 0.2）→ **TRANSIENT**，**再刷一次**就好
- [ ] `file_age_s` **很大**（如 6662）→ **REAL_PROBLEM**，别重试，**直接切回放页**

## 判定标准速查

| 检查 | PASS | FAIL 时的兜底 |
|---|---|---|
| 端口 | 有 ≥2 个空闲端口 | 换端口范围 8790–8799 |
| 服务 | `/`、`/app.js`、`/api/config` 都 200 | 换端口重启；再不行走回放页 |
| mock 标识 | amber 条可见、文字逐字相符 | 口播时明说"标识没渲染出来，但数据来源是模拟的" |
| 额度 | 余量 ≥ 13 次 | 余量变少 → 模式 B；归零 → 全程模式 C |
| 缓存 | 强刷后无白屏、无 console 错误 | 换端口 → 回放页 → 截图 |
| 回放页 | 能打开、能滚到底 | 重新 build；仍不行 → 截图 |
| 截图 | ≥15 张，INPUT 恰好 6 张 | 从 `web/.tmp/demo-rehearsal/shots/` 补拷 |
