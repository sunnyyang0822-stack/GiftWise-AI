# 现场演示素材包（docs/demo/pack）

给 10 分钟现场演示用的**真实截图 + 真实终端输出**。所有图都是本机 Chromium 真渲染出来的，没有一张设计稿、PS 图、或从别的时段搬来的截图。

- 生成时间：2026-10-31 02:10–02:19 +0800（下次重跑会刷新 `MANIFEST.md`）
- 规模：`shots/` 24 张 PNG，合计 **5,791,928 字节（5.52 MiB）**，单张最大 408 KB
- 对应 `docs/demo-script.md` 第六节素材清单里的 **D2 / D4 / D5 / D8 / D9 / D10**；D1 / D3 / D6 / D7 见 [`MISSING.md`](./MISSING.md)

## 目录里有什么

```
docs/demo/pack/

├── MISSING.md                  ← 没拍到的、为什么、谁在哪个界面补

└── terminal/                   ← 9 份真实命令输出（含执行时间与执行目录标注）
```

## 一条命令重出全部截图

```bash
cd <仓库根>
node docs/demo/pack/capture.mjs
```

脚本自己会做完这些事，**不需要预先起服务**：

1. 杀掉 8787 上任何已有监听进程（防止截到**别的工作区**的服务）；
2. 从**本工作区** `web/` 显式起 `node server/server.mjs`（`GW_PORT=8787`）；
   > ⚠️ **2026-10-31 更正（只针对 8787 这个地址）**：上面两步是**本次冻结截图当时**的过程。今天 **`http://127.0.0.1:8787` 不能当作"本工作区"的服务地址** —— 8787 上曾挂着**另一个仓库副本**的服务（`GET /` 返回 **21,039 B**，而本工作区磁盘是 **20,724 B**）。现场**只认 `bash docs/demo/bin/servers.sh start` 打印的端口**，并用 `/` = **20,724 B**、`/landing.css` = **24,981 B** 判身份；不符就改开 `docs/demo/replay/offline-replay.html`。
3. 跑共用一致性自检（`web/tools/server-identity.mjs`）：服务返回的 `/landing.css`、`/` 字节数必须等于磁盘上的 `web/public`;
4. **额外资产指纹**：对首屏加载的全部 9 个静态资产逐个比对「服务返回 = 磁盘」并记录 sha256，开拍前、收工后各一次，两次必须相同（防截图期间被别人改了 CSS）；
5. 用 `chrome.exe`（headless=new）真实驱动 5 组场景、24 张图；
6. 复核首屏请求条数与字节数（与冻结口径比对，**只测量不改口径**）；
7. 只对超过 400 KB 的图做体积处理：先无损重编码，仍超限才逐步降到 256/192/128/96/64 色板 —— **不裁剪、不改内容**；
8. 删掉临时 Chrome profile（放在系统临时目录，交付目录里不会留浏览器内部文件）；
9. 重新生成 `MANIFEST.md`。

可选参数：`--only=D5-01`（只重出匹配的那几张，且不覆盖 MANIFEST）、`--no-optimize`（跳过体积处理）。

**环境依赖**：Node ≥ 22（用了全局 `WebSocket`）、Chrome（默认 `C:\Program Files\Google\Chrome\Application\chrome.exe`，缺省回退 Edge）、Python + Pillow（体积处理用；本机为 `C:\Users\lenovo\AppData\Local\Programs\Python\Python312\python.exe`）。
**不依赖**：Dify、任何模型 API、任何第三方 npm 包（脚本 0 依赖）。全程 **0 次模型调用**。

## 本包**能**证明什么

- 本工作区 Web 界面在**真实 Chromium** 下的样子，且**每一张都能看到常驻吸顶的「模拟数据 · 未接真实模型」标识**（D10-01/02/03 三种视口、D4/D5 系列滚动后仍可见）。
- 正常路径的完整链路：三步表单 → **恰好 3 个**候选 → 四段呈现 → 选择后复核（礼物＋包装＋贺卡＋装饰＋配送）。
- 失败路径**不伪装成功**：`model_error`（空候选）、超时（中文说明 + 重试入口）、记录失效空态、超预算 `OVER_BUDGET`（呈现侧首次复核失败框）。
- 失败项**不可选择**：`?demo=partial_fail` 下仍恰好 3 个候选，被拒绝那张显示「未通过，不可选择」+ 错误码，**没有**选择按钮。
- 本机交付物与验收数字：镜像 tag/体积/构建时间、容器 `/healthz` 与规则文件哈希一致、688 项测试全绿、74 组 parity 零差异、冒烟 59 / 接入层 40 全过、首屏 0 个外部/CDN 请求。

## 本包**不能**证明什么（红线）

- ❌ **不能**证明「已上云 / 已部署 / 多副本 / 高可用」：这里只有**本机**回环端口上的一个进程和一个本机容器。
- ❌ **不能**证明 Dify 工作流真的跑通了：本包 **0 次 Dify 调用、0 次模型调用**，接入层是 `mode: mock`，页面上也是这么写的。Dify 侧的画布 / 节点输入输出 / token 总账**一张都没有** → 见 [`MISSING.md`](./MISSING.md)。
- ❌ **不能**证明真实价格、库存、物流、交付：界面上自己标了 `not_verified`，图里也能读到。
- ❌ **不能**证明真机（安卓/iOS）表现：只有 Chromium 设备模拟（390×844 / 320×640）。
- ❌ **不能**把 `terminal/D9-over-budget-validate.txt` 说成「Dify 给出的拒绝」：那是**本机交付镜像**的校验器回答。

## 看图时注意两个渲染假象（不是造假，是 Chrome 的已知行为）

1. **整页图里的吸顶栏会被"重画"一次**：`D10-05`、`D2-01/02`、`E3-01`、`E4-01`、`D5-01/06` 这类整页截图（`captureBeyondViewport`）中，`position: sticky` 的顶部横幅会被画在**当前滚动位置**，所以它可能出现在画面中部而不是最顶端。**要看吸顶效果，请用视口截图**：`D10-01`、`D10-04`、`D4-02`、`D5-02`～`D5-05`。
2. **整页图里可能出现一个"跳到主要内容"的小标签**：那是无障碍跳转链接，真实存在，只是在整页渲染时才看得见。

## 现场演示怎么用（10 分钟的建议顺序）

| 顺序 | 用哪几张 | 讲什么 |
| --- | --- | --- |
| 开场 | `D10-01` + `D10-04` | 首页与「模拟数据」标识，先把边界说清楚 |
| 输入 | `D2-01` → `D2-02` → `D2-03` | 三步表单，基线填写（追求对象 / 200 元 / 2 天 / 不着急） |
| 三候选 | `D4-01` + `D4-03` | 恰好 3 个；失败项**不可选择**（前端也拦） |
| 选择后 | `D5-01` + `D5-02`～`05` | 四段呈现，且**选择后**才生成细节 |
| 出问题时 | `E1-01`、`E2-02`、`E3-01`、`E4-01` | 四种失败/边界都不伪装成功 |
| 工程底子 | `terminal/D688` + `D74` + `D59` + `D8-*` | 688 项测试、74 组 parity、镜像哈希与 `/healthz` 对上 |

> 演示时若有人问「这是设计稿吗」——`MANIFEST.md` 里有每张图的**真实截取时刻和 sha256**，`capture.mjs` 可以**当场重跑**出一模一样的图，这是本包最硬的回答。
