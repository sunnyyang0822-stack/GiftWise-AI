# 故障处置卡（Demo 现场）

> **用法**：打印一页放手边。出问题时**先说话术，再动手**——观众只在意你有没有失控，不在意你修得多快。
> 每张卡三样东西：**症状** → **一句话处置话术**（照念）→ **备用演示路径**（照做）。
>
> 卡片按"最可能先发生"排序。**C1–C4 是 PM 指定必须覆盖的四种**；C5 之后是本轮预演实测出来的真实故障点。

---

## 先记这一条：通用兜底动作

**任何一段卡住、超过 15 秒没动静**，就念这句，然后切离线回放：

> **「为了不占用各位时间，我切到本地离线回放——这里跑的是同一套归档数据，不是现场重跑，我把这一点说明清楚。」**

然后在地址栏输入（书签栏也放一份）：

```
file:///C:/Users/lenovo/Desktop/giftwise/docs/demo/replay/offline-replay.html
```

这个文件**自包含**：零 CDN、零字体、零图片、零 fetch（本轮已验证 `外部依赖：0`），断网/断额度/白屏都能演。

|---|---|
| **症状** | `cloud.dify.ai` 转圈、502、登录态失效、或企业网络拦截 |
| **话术** | **「Dify 控制台这边访问不通，但演示不依赖它——我用本地归档的同一次运行记录继续，数据是那一次真实跑出来的。」** |
| **备用路径** | ① 打开 `docs/demo/replay/offline-replay.html` → 看 **R-01 / R-02** 块（归档真实模型输出与运行汇总）<br>② 若要展示编排结构，改看 `docs/demo/shots/` 里的流程图截图<br>③ 需要说明版本状态时，念 **D-01** 块：工作流**已发布为版本 #2** |
| **不要做** | ❌ 不要在现场反复刷新控制台（会吃掉宝贵的 3 分钟）<br>❌ 不要说"我们没发布"——**已经发布了**，说反了会被追问 |
| **复现证据** | 本轮实测：本机 `https://` 整体不可用（见 C6），控制台从未联通 |

## C4 · 页面白屏

| 项 | 内容 |
|---|---|
| **症状** | 主页面打开是空白、只有背景色、或 JS 报错导致不渲染 |
| **话术** | **「前端这次没渲染出来，我换用离线回放页继续——内容是一样的，我把数据来源说明一下。」** |
| **备用路径（按序试）** | ① **先按 `Ctrl+Shift+R` 强制刷新**（本轮已确认：其它 Agent 正在写 `web/public/`，读到半截文件会白屏，一次强刷通常就好）<br>② 还不行 → 换端口：`GW_PORT=8791` 重启本机服务<br>③ 还不行 → `file:///…/offline-replay.html`<br>④ 最后兜底 → 首屏截图 `docs/demo/shots/RES-1920x1080.png` |
| **判定"是不是暂时性"** | 用 `node docs/demo/bin/retry-on-404.mjs <file>`：<br>· `file_age_s` 很小（如 0.2）→ **TRANSIENT**，重试即可<br>· `file_age_s` 很大（如 6662）→ **REAL_PROBLEM**，别重试，直接走兜底 |
| **⚠️ 诚实提醒** | 本轮 25 秒并发探测（62 个样本）**没有复现**白屏，`transient_failures_observed: 0`。所以这条是**防御性预案**，不是已复现故障——**不要说"我们知道它一定会白屏"** |

## C5 · 服务起不来：端口被占用（🔴 本轮**已复现**）

| 项 | 内容 |
|---|---|
| **症状** | 按脚本原命令起服务，终端刷出**一大段红色堆栈**然后退出 |
| **真实报错** | `Error: listen EADDRINUSE: address already in use 127.0.0.1:8787`，随后 `node:events:505 throw er; // Unhandled 'error' event` |
| **根因** | `web/server/server.mjs` 的 `listen` **没有挂 `error` 事件处理器**，所以端口占用会变成**未捕获异常直接崩进程**，不是友好提示 |
| **话术** | **「端口被别的进程占了，换个端口就行。」**（一句带过，不要解释堆栈） |
| **备用路径** | ① 用我的启动器（**会自动避开占用端口**）：<br>`bash docs/demo/bin/servers.sh start`<br>② 手动指定：`GW_PORT=8791 node web/server/server.mjs`<br>③ 查看占用：`bash docs/demo/bin/servers.sh status` |
| **⚠️ 现场风险** | 样例脚本写的就是 `GW_PORT=8787`，而 **8787 在现场很可能被别人占着**。**开演前必须确认端口**（见 `预演检查表.md`） |

## C6 · HTTPS 整体不可用（🔴 本轮**已复现**，非场地结论）

| 项 | 内容 |
|---|---|
| **症状** | 任何 `https://` 都失败：`curl` 返回 `code=000` / exit 35；浏览器证书错误 |
| **真实报错** | `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)`；Python：`CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate` |
| **已排除** | 不是断网：`http://www.baidu.com` 返回 **200**。是**本机 HTTPS 通道**问题（`nslookup cloud.dify.ai` 解析到 `198.18.0.94`，属保留段/拦截代理） |
| **话术** | **「这台机器上 HTTPS 通道不可用，所以今天全程走本地归档——我不会假装它连通了。」** |
| **备用路径** | 模式 B/C 全程可用，**S1–S4 都能演完** |
| **⚠️ 诚实边界** | 这**只是本机**的复现结果。**场地能不能连 HTTPS / 能不能打通 Dify 属未核实**，不要拿本机结论推断场地 |

## C7 · 模型调用挂住 / 超时

| 项 | 内容 |
|---|---|
| **症状** | 点了"生成三个方案"，界面一直转圈不返回 |
| **好的一面** | **这一条系统做对了**（本轮已验证，零额度）：超时会**明确失败**而不是假装成功 |
| **真实返回** | HTTP **503** + `DIFY_TIMEOUT`：「Dify 调用超过 1500 毫秒未返回，已按超时处理。」**实测 1633 ms 就返回了**，进程不崩 |
| **话术** | **「模型调用超时了。注意这里的处理方式：它没有编三个假方案给我，而是明确报错——这是我们要的行为。」** |
| **备用路径** | 把这个错误**当成演示亮点**念完，然后切模式 B 继续 |
| **⚠️ 对比参考** | 未配密钥时返回 `DIFY_NOT_CONFIGURED` + HTTP 503 + 「真实 Dify 调用未成功，未生成任何候选，也没有把模拟数据伪装成真实结果。」——这句原文很适合现场念 |
