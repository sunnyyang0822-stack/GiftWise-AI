## 逐项发现与 PM 处理

1. **预算稿 §3.1 与 §5.4/E9 不一致**：前者要求 min/max 都是金额字符串，后者允许 min=null。新表单两端均必填，不允许 null；旧标量请求仍兼容，视为没有软下限。前端旧 `budget_range` 是档位 ID（`web/public/app.js:50,287`），不能直接装入新对象。
2. **预算稿 §3.1 有 320/345 数量矛盾，§3.3 声称回归风险为零不成立**。新增校验即使不改候选比较也会改变请求上下文。零预算与 0.99 等期望须重算；预算为 0 且天数 366 仍应被天数规则拒绝。不得把三条网格都称为整体转为合法，也不得预填新通过数。
3. **预算稿 §6.3 只把 revisedTotal 改为 originalTotal 仍不完整**：`web/server/checker.mjs:496-503` 同时要求 additional_cost 与 revised_estimated_total；`web/server/pipeline.mjs` 和前端仍展示这些数值。新契约禁止包装报价，不能留着数值仅藏界面，也不能用 0.00 冒充包装免费。新呈现明确版本，移除新增包装费用字段，按礼物金额复核；旧记录按旧版本读取或拒绝，禁止偷偷重解释。
4. **预算稿 §6.4 的“JS 独立规则没有 Python 兜底，所以有张力”推论不成立**。代码校验是否独立取决于是否独立于模型，不取决于编程语言。确实存在“呈现未纳入既有跨语言 parity”的覆盖缺口，应补 JS 独立单测和接口验收，不为了对称新建 Python 呈现服务。
5. **AI 稿 B6/C11-B/R1/R12 允许未映射禁忌放行，不采纳**。用户本轮已经确认无法可靠识别则澄清；删除旧输入框不等于删除阻塞语义。识别为空、无效 JSON、依据不合规、未映射均不能当作“没有禁忌”。
6. **AI 稿 B7 先生成候选再确认约束，存在时序问题**。改为收集“不喜欢”与补充说明 → 识别 → 同页确认/澄清 → 服务端冻结约束 → 三方案 → 校验 → 用户选择。识别不能用自动业务修订来重试，不得重置全局一次修订额度。
7. **AI 稿 B5/B6 逐字子串与归一化子串定义冲突**。source_span 必须为原文精确连续子串；term 可用 NFKC+casefold 校验它与 span 的包含关系。两者都仅证明文字来源，不证明理解正确。类别、否定、指代、同义词都要靠用户确认与明确能力边界，不能宣称完全防漏判。
8. **AI 稿 A3 的“字面词在 mock 下没有去向”不准确**。`notes` 不被 mock 使用，不等于 `hard_exclusions.terms` 不被使用；`web/server/intake.mjs:186` 映射为 forbidden_terms，`validator/rules.py:211-213`/JS 对等实现实际拦截。原稿应作为设计时推论阅读，不能复制为事实。
9. **AI 稿字段存储/日志边界需收紧**。运行期临时快照可持有输入，公开运行日志与归档不写用户原文。只输出虚构夹具、摘要、计数、指纹；不要把 raw 模型/用户输入持久化当审计功能。
10. **前端稿 §1.2 关于进度 nav 不包含四主题的说法有误**。`web/public/app.js:157-175` 确实追加四个 pill。三页/四主题会混淆，但不能从此断言 nav 标签覆盖所有后代语义、读屏一定如何朗读。新版本统一三页三步和 aria-label；原证据只能证明静态结构。
11. **前端稿 §3.1 的“建议 5 天与 3–7 天不一致”不是缺陷**，5 在区间内；开放区间只列部分建议也不矛盾。真正问题是配置与前端映射双维护。新六档统一由配置下发。
12. **前端稿 §5 的绝对化判断不采纳**。同步 render 不保证用户一定看到加载帧；定时器也不保证精确 20 秒切换。45 秒是服务端延迟，20 秒是客户端等待阈值，二者并非文案自相矛盾。要以浏览器运行验证实际加载/超时/恢复，不凭静态分析报已通过。
13. **前端稿 §6.4 “零新增费所以含包装成立”不成立**。0 是模型/模拟字段，不能证明材料免费或估价构成。新账单明确只统计所选礼物，包装不计价，绝不把三个备选的价钱相加。
