## 3. 🔴 十二条红线（违反会毁掉交付）

1. **`git update-ref` 不更新索引。** 每次改完 ref 必须 `git read-tree HEAD`，并断言 `git diff --cached --name-only` 为空。
2. **绝不要 `export GIT_INDEX_FILE`**。只在**单条命令前缀**上用（`GIT_INDEX_FILE=$tmp git ...`），用完删掉。
3. **绝不用 `2>/dev/null` 吞 git 写操作的报错。** 上一任 PM 就是因为吞了 `git update-index --cacheinfo` 的报错，
   造出 **10 条内容为空的分支 + 10 个空 PR**（PR #30–#39 已全部关闭并写明原因）。写入操作必须让报错露出来。
4. **绝不用 `git diff --quiet A B -- <path>` 作为"写入成功"的自证。** 上一任 PM 用它自检，报出「29/29 逐字节一致」的
   **假绿**，实际是 0/29。**唯一可信的自证是比对 tree / blob 的哈希**：
   ```bash
   git rev-parse <分支>^{tree} <基准>^{tree}          # 两个哈希必须不同
   git rev-parse <分支>:<文件> <集成分支>:<文件>      # blob 必须相同
   ```
   这条对本项目**普遍适用**：任何"改完了/写进去了"的结论，都要用**独立于写入路径**的证据来证。
5. **一个工作目录只能处在一个分支上。** 主工作区**不要切分支**（不 checkout / switch / branch / merge / rebase / reset / stash）。
   要并行就 `git worktree add <兄弟目录> -b <新分支> <基准>`。主工作区的当前分支必须始终是 `release/2026-11-01-submission`。
6. **绝不把子 Agent 的自报当成事实。** 用户的常驻指令原文：「夜间工作中你如果发现单独的子agent完成后你验收审核一下」。
   每个 Agent 交付后都要**独立复核**（自己去看文件、自己跑命令），不许转述它的结论。
7. **B 类文件里的数字永不改写，只加时点注。** B 类 = `workflow/evidence/**`、`docs/pm-reviews/**`、`docs/test-reports/**`。
   它们记录了"当时发生了什么"，改数字等于伪造历史。要修正就**前置**一句"（YYYY-MM-DD 注：…）"。
8. **绝不把未完成的事写成已完成。** 见第 8 节「绝不能宣称已完成」清单。
9. **静态 Markdown 里不钉 SHA。** 写"现场跑 `git ls-remote` 看"，不要写死提交号（提交号会变）。
10. **不动留痕原件。** `docs/competition/答辩PPT-GiftWise.pptx`（400,178 B，sha `f1d1057f…`）是**留痕、不交付、一字不动**。
    交付投影是 `docs/competition/答辩PPT-GiftWise-修订版-2026-10-31.pptx`。
11. **不花 Dify 额度。** 产品的模型调用额度累计 **13 次 / 38,326 tokens，上限 16**，**只剩 3 次，全部留给 11-01 现场 Demo**。
    夜间与日常工作中**一次都不能用**。

## 9. 流程规范

### 分支模型（`docs/branch-and-pr-process.md` 是权威）
- `main` = **交付主干**，评委看到的就是它，**只接受 PR 合并**
- `release/2026-11-01-submission` = **集成分支**
- `line/<线名>` = 分线分支，**一个分线 = 一个 PR = 一个合并决定**
- `batch/<批次名>` = 跨线打包
- §3「**不允许"挂着不管"**：每个 PR 最终必须落到**已合并**或**已关闭**（关闭必须写明原因）」
- §4「**快照式分线分支**」
- ⚠️ 第 48 行：「**一个目录只能处在一个分支上**」

### 提交的正确技术（**plumbing，不切分支**）
```bash
BASE=$(git rev-parse HEAD)
TMP=$(mktemp)
GIT_INDEX_FILE=$TMP git read-tree "$BASE"          # 只在单条命令前缀上用
# …用 git update-index 改索引（不吞报错！）…
TREE=$(GIT_INDEX_FILE=$TMP git write-tree)
COMMIT=$(git commit-tree "$TREE" -p "$BASE" -m "…")
git update-ref refs/heads/<分支> "$COMMIT"
rm -f "$TMP"
git read-tree HEAD                                  # 必须
git diff --cached --name-only                       # 必须为空
git rev-parse <分支>^{tree} "$BASE^{tree}"          # 必须不同 ← 这才是可信自证
```
仓库 `.tmp/` 下已有可复用脚本（**gitignored**）：`commit-generic.sh`（消息放 `.tmp/msg.txt`，
未跟踪的新文件要写进 `.tmp/extra-paths.txt`）、`push-merge-generic.sh <消息尾>`。

### 派发给子 Agent 的**统一协议块**（每个提示词都要带）
```
⚠️ 禁止任何 git 分支操作（checkout/switch/branch/merge/rebase/push/reset/stash）
🛑 禁止任何外部网络 / Dify / 浏览器驱动 / 模型调用
```
外加：只改指定文件、结论必须落到 `文件:行号`、区分【实测】与【推断】、
自报格式六段（含"未执行任何 git 写操作"）。
若要允许子 Agent 自己开 PR，则改为：**只在自己 worktree、只推自己分支、只开一个 PR、不合并**。
