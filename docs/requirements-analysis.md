## 1. 用户与动机（冻结）

- **主要用户：青年人群，尤其初入社会的青年。**
- **核心动机：** 不知道送什么；担心选错礼物造成尴尬、误解或其他负面效果。
- 次要人群：青少年（主要给朋友送礼，关注是否符合对方真正想要的）、中年人（以职场送礼为主，当前假设需求强度较低）。**此类人群判断是定位假设，不得据年龄或职业编造个人喜好。**
- 年龄人群优先级与关系场景优先级是两个独立维度。

## 2. 关系场景优先级（冻结）

| 优先级 | 关系 | 冻结说明 |
| --- | --- | --- |
| 1（最高频核心目标） | **恋人**、**追求对象** | 推荐理由、产品案例、包装、贺卡与赠送方式优先服务这两类关系 |
| 2 | 朋友 | |
| 3 | 职场上司、亲戚家人等 | |
| 覆盖但不主导 | 同事、老师/导师、客户/合作伙伴等 | **同事生日案例仅保留为技术回归基线**，不代表最高优先级用户 |

**硬性需求（冻结，不可被实现方省略）：**

1. **恋人与追求对象不能合并为同一亲密程度。** 追求关系不代表对方已接受或存在双向好感。
2. 推荐与贺卡**不得假设对方心意或承诺关系结果**；应根据已知关系与熟悉程度给出合适表达，**避免制造回应压力**。
3. "最高频"是产品负责人确定的目标场景优先级，**尚无真实使用频率数据**，不得写成已验证的用户统计。

## 3. 核心痛点（冻结）

| 编号 | 痛点 | 现状与 Agent 增量 |
| --- | --- | --- |
| P-1 | 不知道送什么 | 普通聊天式推荐直接给想法，难以证明依据、硬约束与修改边界；本产品须给出三个**有依据**的思路 |
| P-2 | 担心选错造成尴尬或误解 | 需区分**用户事实 / 模型推断 / 仍未知**，不得编造对方偏好 |
| P-3 | 关系表达过强或过弱 | 恋人与追求对象必须使用**不同**提示、风险说明、贺卡语气与赠送话术；追求对象默认低压力 |
| P-4 | 预算、准备时间与明确禁忌冲突 | 需**独立代码校验**硬约束，模型不得覆盖用户预算、天数或明确禁忌 |
| P-5 | 包装等新增成本是否仍可控 | 选择后才生成呈现内容，且新增费用、时间与材料禁忌继续受原始约束限制 |

## 4. MVP 核心闭环（冻结，6 步）

1. 用户输入关系、场合、预算、兴趣、风格、禁忌、准备时间等已知信息；**未知可以留空，不编造**。
2. 系统给出**三个不同思路**的礼物选项，逐一解释为什么选它，并区分用户事实、模型推断与仍未知的信息。
3. **独立代码校验**预算、币种、禁忌、必要字段与估算准备时间；失败后**最多一次**自动修订并重新校验，仍失败则如实报告。
4. **用户自己选择**一个已通过检查的方案，系统不擅自替选。
5. **选择后**才提供该礼物的包装材料与步骤、配色、可用贺卡文案、赠送时机与话术。
6. 包装等新增成本、时间与材料禁忌继续受原始约束限制；**同一送礼任务跨两个阶段合计最多一次自动业务修订**。

## 5. 成功标准（冻结，可验证）

| 编号 | 成功标准 | 验证方式 | 计划阶段 |
| --- | --- | --- | --- |
| SC-1 | 用户能完成三步输入，且**预算上限与最终可用天数被明确展示与确认**，无静默补值 | 表单状态与提交载荷比对；边界用例 | 7、9、11 |
| SC-2 | 系统生成**恰好三个不同**候选，并分离事实／推断／未知 | 固定快照 + 真实模型输出各一组 | 9、11 |
| SC-3 | 规则校验**独立于模型**，失败项**不可选** | 校验器返回与前端可选列表一致性测试 | 9、11 |
| SC-4 | 恋人与追求对象使用**不同**提示、文案与话术；追求对象不默认告白、承诺或关系确认 | 两个关系各一组端到端中文输出比对 | 11 |
| SC-5 | **选择前**不生成任何详细包装／贺卡／赠送设计 | 调用轨迹与状态机检查 | 10、11 |
| SC-6 | 选择后严格按"风格配色 → 包装 → 贺卡及装饰 → 赠送时机与话术"呈现，并复核总费用、准备时间与禁忌 | 端到端输出顺序断言与复核结果 | 11 |
| SC-7 | 跨阶段自动业务修订**合计不超过一次**，且次数不可由前端篡改 | 可信状态持久化 + 篡改测试 | 9、11 |
| SC-8 | 中文状态完备：加载、空状态、错误、超时、无可选方案、未选择 | 页面状态清单逐项复现 | 11 |
| SC-9 | 所有失败路径**不伪装为完成**，且保留可解释的失败原因 | 故障注入用例 | 9、11 |

**目标而非已达成（不得提前宣称）：**

- 约 **60 秒**完成初始输入（Issue #3 要求记录试用方法与真实耗时，**当前无真实用户测量**）。
- 三个候选是否足够、事实／推断／未知分离是否提升信任、包装与装饰是否可执行、延迟与费用是否可接受：**均为待验证假设**。

## 7. 边界与非目标（冻结）

- 后置：精致视觉、复杂账号、长期记忆、多 Agent 产品能力、购物支付、实时商品集成。

- 网站默认简体中文：导航、按钮、操作提示、加载状态、错误反馈与生成内容均使用中文；机器字段、错误代码、库名与项目名可保留原标识符。
- 部署要求先向主办方核实，**不编造规则或运行证据**。
- 同事生日不作为产品主场景与验收案例，仅作技术回归。
