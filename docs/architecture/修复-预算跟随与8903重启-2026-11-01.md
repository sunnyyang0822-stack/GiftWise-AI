**为什么 `budget_range.max` 只能取用户原值**：契约与硬校验（`intake.mjs:100`、`checker.mjs:539`）都要求
`budget_range.max === budget_amount`。因此：

- `budget_amount` = 用户文本给的确定值 → **界面显示的就是他输入的东西**（裁定 2）；
- `budget_range = {min: 值−50, max: 值}` → 两个端点都落在 **±50** 内，且 `max === budget_amount` ⇒ 校验通过；
- 「+50 的那一侧」完整保留在 `parse.constraints.budget_band`（`{min:750,max:850}`），与
  `pipeline.mjs:applyInputParseGates` 的候选侧 gate 共用同一份常量；实际生效区间是 `[值−50, 值]`，
  因为上界被既有 `OVER_BUDGET`（≤ 用户所给值）兜住 —— 这正是 `pipeline.mjs` **原本就写明**的口径。
- 天数侧本来就是对的，未改：`deadline_days` = 用户给的天数，`days_band = {N−1, N+1}`。

### 1.3 区间输入「预算 800–1000」的行为（新增）

提示词要求模型只给**单个**金额；模型对区间的处理实测不稳定（两次真实调用里，一次把 800–1000 读成 `1000`，
一次干脆没输出 `budget`）。因此按与 `deadlineCrossCheck` 同一思路，用**用户原话**做代码级区间识别：

```js
const BUDGET_KEYWORD_RE = /预算|价格|价位|花费|¥|￥|RMB|人民币/u;
const BUDGET_RANGE_RES = [
  /(?:预算|价格|价位|花费|大概|大约|¥|￥|RMB|人民币)[^\d\n]{0,6}(\d{1,6}(?:\.\d{1,2})?)\s*[-–—~～至到]\s*(\d{1,6}(?:\.\d{1,2})?)/u,
  /(\d{1,6}(?:\.\d{1,2})?)\s*[-–—~～至到]\s*(\d{1,6}(?:\.\d{1,2})?)\s*(?:元|块|人民币|以内|左右)/u,
];
export function budgetRangeFromText(text) {
  // 有金额语境词 ⇒ 只认正则 1（贴着语境词的区间）；没有语境词时才允许「800-1000 元」这种单位在后的写法。
  const candidates = BUDGET_KEYWORD_RE.test(text) ? [BUDGET_RANGE_RES[0]] : BUDGET_RANGE_RES;
  ...
}
```

行为表（实测，逐条跑过）：

| 输入 | `budgetRangeFromText()` | 结果 |
|---|---|---|
| `预算 800-1000` | `800-1000` | 区间分支：`budget_amount="1000"`、`budget_range={800,1000}`、`budget_band={750,1050}` |
| `800-1000 元`（没有语境词） | `800-1000` | 同上 |
| `送礼预算 500~800` | `500-800` | 同上 |
| `预算 800 到 1000 元，越快越好` | `800-1000` | 同上 |
| `预算大概一千，实际 800-1000 元之间` | `800-1000` | 同上 |
| **`预算 200，运费 10-20 元`** | `null` | 退回确定金额路径（= 用户说的 200），**不会**把运费区间当预算 |
| `预算 200 左右，运费 10-20 元` | `null` | 同上 |
| `预算 500 元，需要 3-5 天` | `null` | 同上 |
| `预算 800 左右` / `价格 2000 元` / `2026-11-01 要送到` | `null` | 不是区间（日期/编号不误判） |

> 为什么要加这条「有语境词就只认贴着语境词的区间」：我第一版会把「预算 200，运费 10-20 元」读成 10–20，
> 把用户真正说的 200 抹掉 —— 这是我自己实测发现的误判，已在 22:16 修掉并加 3 条反例单测。
> 宁可少认一个区间（退回模型给的单个金额，仍是用户说的那个数），也不能认错。

区间与模型单值冲突时**不静默**，写进 `parse.budget_check` 与 `parse.notes`（第一次真实调用的原文）：
