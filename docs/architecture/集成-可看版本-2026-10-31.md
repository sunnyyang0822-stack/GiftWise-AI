## 0. 先看这里：怎么打开、点什么

**URL**：<http://127.0.0.1:8902/>

打开后是一个中文聊天式表单页，操作路径：

1. **填需求**：关系场景（如「恋人及追求对象」）、场合、预算、可用天数、兴趣、礼物风格；
2. 点提交 → 前端真实 `POST /api/recommendations` → **真实调用大模型**（实测约 **29–43 秒**，推理模型思考占大头，请耐心等）；
3. 页面出现**恰好 3 个方案**（含图片卡位、价格、准备时间、排除项命中说明）；
4. **选一个方案** → 前端真实 `POST /api/presentations` → 真实调用大模型做四段呈现（约 **10–19 秒**）；
5. 呈现复核通过后服务端自动提交**真实生图**（约 **8–9 秒**），页面轮询 `/api/media/tasks/<task_id>`，图片就绪后显示 AI 包装效果图。

**整个流程约 60–90 秒**（主要是大模型推理耗时），期间页面上有进度提示，不是卡死。

### 1.3 取舍理由（逐条）

**① 用 `gw-flow` 当基座，而不是从 c5736c2 一件件拼。**
`gw-flow` 的改动量最大（`1437 insertions`），且它**已经是一个局部集成体**——
它自带 `web/server/llm/`、`localdb/`、`catalog/`、`visual/`、`collect/`，
并且已经包含 `IMAGE_GENERATION_CONFIG` 与 `enableImageGeneration` 显式授权闸门。
以它为基座省掉了 llm 线与 localdb 线在 `config.mjs` / `server.mjs` / `pipeline.mjs`
上的三方冲突合并，这是「最快速度」的关键决定。

**② `gw-flow` 的 `llm/` 比 `gw-llm-direct` 的更新 ⇒ 不反向覆盖。**
`gw-llm-direct` 的 `provider.mjs` 导出 `promptSourceOf`、`requestCandidates` 只有
`{requestJson,intakeJson,retrieval}`；`gw-flow` 的版本**去掉了 `promptSourceOf`**、
并新增 `library` 参数（把库里真实存在的商品随信封一起给模型，避免模型凭空想出买不到的东西）。
后者是**库优先**能力的前置条件，功能更强 ⇒ 采用 `gw-flow` 版本。取 `gw-llm-direct` 反而会退化。

**③ `media/provider.mjs`：保留 `gw-flow` 版本，只嫁接 imagegen 的两类改动。**
两者是**互补而非覆盖**关系：

- `gw-flow` 版独有且必须保留：
  - `candidates()` 会**保留真实商品图**（`kind==='source_photo'` 且 `url` 以 `/` 开头），
    而 imagegen 版是 `image:null`（会把真实商品图抹掉）——这直接决定 §3.3 能不能看到真实商品图；
  - 未授权分支用 `fingerprint(...)` 造 **64 位十六进制** task_id，匹配
    `/api/media/(tasks|assets)/[a-f0-9]{64}` 路由；imagegen 版用 `randomUUID()`，
    会落到 405/404 而不是诚实的响应。
- 从 `gw-imagegen` 嫁接进来的（共 3 处 + 1 个常量）：
  - `REFERENCE_IMAGE_HOSTS` 常量与 `new SeedreamProvider({referenceHosts:[...]})`——参考图 host 白名单；
  - `generation` 增加 `reference_status` / `http_status` / `byte_length`；
  - 失败分支增加 `reference_count:0` / `reference_status:'not_submitted'`（**参考图被拒时绝不假装成功**）。

**④ `localdb` 放进独立目录 `web/server/localdb-real/`，不覆盖 `web/server/localdb/`。**
两条线各有一个 `localdb/db.mjs` 且**内容不同**：`gw-flow` 的 `localdb/db.mjs` 被
`collect/collect.mjs`、`catalog/match.mjs` 依赖；`gw-opencli-db` 的 `db.mjs` 才导出
`defaultDbPath / queryProducts / getStats / getProductImages / compareQuotes`。
若直接覆盖会**打断工作流的采集链路**。因此把 opencli 线的
`{catalog,db,schema,scene-pool,scene-pool-catalog}.mjs` 整体放进
`web/server/localdb-real/`——目录内相对 `./db.mjs` 引用自洽，**零冲突**。

**⑤ 前端：先验证「真能调通」再取 ⇒ 结论是能，故接入。**

### 4.1 先纠正一个容易搞错的前提：**站点适配器也需要 Chrome，但不需要扩展**

任务书假设「站点适配器（`opencli web read` / `smzdm …`）不需要浏览器扩展、不需要 Chrome」。
代码里的**实测记录与此不完全一致**，必须如实分开写：

- **不需要的是「浏览器扩展」**；
- **需要的是「一个 Chrome 可执行文件」**——采集器自己拉起**专用无头 Chrome**，用
  `OPENCLI_CDP_ENDPOINT` 直连 CDP，**绕开**需要扩展的 Browser Bridge。

证据（`web/server/collect/chrome.mjs` 文件头注释，原文）：

```
 * 为什么需要它：opencli 2.0.2 的 170 个站点适配器全部标记 `browser: true`，
```
