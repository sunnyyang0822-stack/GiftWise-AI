# ADR-004：无平台级追踪下的可观测性替代路径

- 状态：**已接受**（2026-10-30）
- 关联：ARCH-001、[可观测性设计](../observability.md)、CLOUD-001（阶段 14）、评分规则赛道 B「可观测性证据」
- 关联成功标准：SC-7（修订次数不可篡改）、SC-9（失败不伪装完成）

## 背景与约束

1. 评分规则赛道 B 要求「关键日志、运行状态、调用记录或指标」，**并明确"不要求所有项目采用相同监控方案"**。
2. **已实测硬约束**：该 Dify 租户 `GET .../trace-runs/workflow/<run_id>` → 200 `{"status":"not_collected"}`，**没有平台级追踪**（WF-002；QA 独立复跑一致）。
3. 赛道 B 另一项要求「工具调用轨迹」，在无追踪的前提下需要**替代证据**。
4. 控制台接口有取证限制：`GET .../workflow-runs` 由脚本直接 `fetch` 返回 **401 CSRF**（属方法限制，不是接口故障）；**点击「测试运行」本身会触发草稿自动保存并刷新 `updated_at`**，故 `updated_at` **不能**作为"内容是否变更"的判据。

## 决策

**不依赖平台追踪，改用三级替代路径 + 版本哈希锚定：**

| 级别 | 手段 | 现状 |
| --- | --- | --- |
| ① 接入层结构化调用记录（`run_id`／状态／错误码／`call_counts`／修订计数／耗时） | 字段已存在并随报告返回 | **E2 已实现；落盘持久化未实现** |
| ② Dify `draft/run` **SSE 节点级事件** + `nodes/<id>/last-run` | `node_finished`／`workflow_finished` 含 `status`／`error`／`elapsed_time`／`total_tokens` | **E1 已实测可用**，已取五类用例逐字原文 |
| ③ 版本锚定哈希（`rules_source_sha256`、`sources_sha256`、`artifacts_sha256`） | 任何校验结论可绑定到确切规则版本 | **E1 已实测** |
| ④ 运行原文归档 `workflow/evidence/**` | 逐字原文 + 服务端时间戳 + 截图 | **E1 已实测** |
| ⑤ 平台追踪 `trace-runs` | — | **本租户不可用**（如实记录，不伪造） |

## 理由

- **可观测性方案必须能兑现**：把方案建立在"平台追踪"上，在本租户会变成空承诺。因此改为**自产证据**：能自己记录的就自己记录，能自己锚定的就锚定版本。
- **SSE 比 UI 更强**（QA §1.6 结论）：它逐节点给出 `status`、`error`、`elapsed_time`、`outputs`、`inputs`、`process_data`，无需依赖页面渲染，**可脚本机械断言**。
- **"没有追踪"本身就是必须如实记录的负面证据**：方案中显式写明 `not_collected`，并给出替代路径，比写"已接入追踪平台"更符合项目纪律。

## 被否决的替代方案

| 方案 | 否决理由 |
| --- | --- |
| 声称已接入 LangSmith／Langfuse 等平台追踪 | 无凭证、无集成、从未调用成功；属于伪造 |
| 依赖 Dify 控制台"日志/监测"页面作为调用历史 | 该租户 `not_collected`，**不会有可查记录**（WF-003 §6.6） |
| 用 `updated_at` 判断草稿是否变更 | **已实测**：点击测试运行会触发自动保存并刷新 `updated_at`，该字段不能作判据 |
| 从页面 DOM 读"上次运行"作为唯一证据 | 弱于 SSE；只能作交叉验证 |
| 记录用户原文以便排查 | 违反隐私红线（§6）；错误响应亦不回显原文 |

## 后果

**正面**：证据链自洽且可被评委直接核验：`run_id` 贯穿任务、SSE 给出节点级轨迹、哈希绑定规则版本、`evidence/` 保存逐字原文。

**负面／已知缺口（未假装解决）**：
- 接入层调用记录**未落盘**：进程重启即失去历史，当前只能靠报告响应与证据归档回看。
- 无指标聚合（P50/P95、错误率）、无面板、无告警、无保留期与采样策略（见成本性能清单 §4）。
- 模拟与真实混用风险靠**显式披露**（`mode`、`notices`）缓解，而非靠技术强制。
- `draft/run` 是**控制台草稿测试运行**接口，不是生产 API；生产路径 `/workflows/run` 在无追踪下**轨迹不可回查**，因此生产化必须补齐 ①。

## 重新评估条件

- PM／产品负责人决定开启租户 trace 采集（→ 可直接复用同一 `run_id` 作关联键）。
- 接入层引入持久化存储（→ ① 升级为真正的调用记录，并补聚合指标）。
- 生产化上线（→ `/workflows/run` 路径必须有自己的记录，不得依赖控制台接口）。
