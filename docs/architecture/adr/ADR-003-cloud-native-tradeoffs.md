# ADR-003：云原生分层取舍——Docker 计划、K8S 不采用、微服务不采用

- 状态：**已接受**（2026-10-30）
- 关联：ARCH-001、`docs/architecture.md` §3.4／§5、评分规则赛道 B「云原生架构与技术选型（15 分）」
- 声明：本 ADR 记录的是**取舍**，不是"已具备云原生能力"。**本项目没有任何已完成的容器构建或云部署。**

## 背景与约束

1. 赛道 B 评分包含「Docker/K8S、微服务、弹性伸缩、资源调度、分布式状态和云基础设施使用合理；**能解释取舍**」。
2. **已实测约束**：真实负载为单用户、低频、会话式；规则计算 p50 **0.166 ms**；接入层 HTTP 往返 p50 **12.545 ms**。
3. **未实测约束**：并发容量、限流阈值、资源消耗**全部未知**；模型未授权导致真实业务负载**未知**。
4. 交付窗口约 35 小时；`deploy/` 归属刚由 CLOUD-001 认领，尚未有构建与部署实测。
5. 主办方是否强制容器/K8S **尚未核实**（`docs/architecture.md` 初版即已列为待确认项）。

## 决策

| 层次 | 决策 | 当前真实状态 |
| --- | --- | --- |
| 确定性规则 | **内联执行**（见 ADR-001） | 已实测 |
| 独立规则 API | **保留可运行实现，但不作为关键路径** | `deploy/server.py` 已实测可运行；未容器化、未部署 |
| 容器化 | **Docker 先做可复现打包（计划）** | `Dockerfile` **从未构建** |
| 编排平台 | **K8S 明确不采用（当前）** | 无 |
| 微服务拆分 | **不采用** | 单一接入层 + 纯函数规则 |
| 托管云主机 | **未采购、未部署** | `publish-to-uhost.ps1` **从未上传** |
| 弹性伸缩／资源调度 | **未实现** | 无 |
| 分布式状态 | **未实现**（当前为进程内存） | 已知限制 |

## 理由

- **K8S 在当前负载下是负收益**：本应用是单用户会话式负载，且真实并发未知。引入 K8S 会带来编排、网络、镜像仓库、密钥与运维成本，而**没有任何已验证的容量收益**可以交换。评分规则明确要求"能解释取舍"，本决策正是取舍：**先证明闭环，再谈弹性**。
- **微服务不采用有实测支撑**：把 0.166 ms 的纯函数拆成远程服务，会把延迟推高到 12.5 ms 量级（本机回环实测），并引入网络故障面。这与"独立校验"的语义要求无关（ADR-001）。
- **Docker 仍然值得做**：它解决的是**可复现性**（评委可复验），而不是伸缩。这是 CLOUD-001 的范围。
- **分布式状态是真正的缺口**：只要接入层持有进程内快照，就无法多副本、也无法跨重启恢复。这是应当优先补齐的项，而不是先上编排平台。

## 被否决的替代方案

| 方案 | 否决理由 |
| --- | --- |
| 直接上 K8S + Helm | 无负载数据支撑；运维面扩大；交付窗口内挤占闭环验证时间 |
| 拆微服务（适配/校验/呈现各自服务） | 实测显示计算极快而传输昂贵；拆分只会放大延迟与故障面 |
| 直接采购 UCloud 实例并部署 | 涉及费用与凭证，需产品负责人授权；且赛题强制要求未核实 |
| 先做前端精修再谈部署 | 违反"最小可演示闭环优先" |

## 后果

**正面**：架构面小、可验证点集中、每个组件都有实测证据或明确标注"未实现"；不会出现"文档写了 K8S 但实际没有"的落差。

**负面／已知缺口**：
- 赛道 B「云原生」维度中，**容器化、弹性伸缩、资源调度、分布式状态四项本项目均无真实验证**；本项得分应基于编排链路与证据完整性，而非容器化程度。
- `deploy/` 与本 ADR 相关的两个真实风险已登记（见 `docs/architecture.md` §9）：
  - **A-1**：`deploy/README.md` 记载的 `python deploy/server.py` 实测失败（`ModuleNotFoundError: No module named 'validator'`），而 `python -m deploy.server` 成功。
  - **A-2**：`Dockerfile` 未 COPY `deploy/__init__.py`，`CMD ["python","-m","deploy.server"]` 依赖隐式命名空间包，**构建后能否启动未验证**。

## 重新评估条件

- 出现真实并发/容量数据（尤其模型授权后测得的端到端延迟与并发劣化曲线）。
- 主办方明确强制容器或 K8S（届时以主办方要求优先）。
- 需要多副本或跨重启恢复（→ 先解决分布式状态，再谈编排）。
- 获得云资源额度与预算授权。
