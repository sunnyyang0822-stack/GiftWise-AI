# 场景质量与决策链验证线（SCENARIO-001）

**存在理由**：竞赛评分第一项是「**场景价值与痛点判断 20 分**」，而在此之前我们只有单元测试与探针，
**没有"一个真实用户从输入到拿到方案"的端到端走查成果**。本线补的就是这一块。

## 一句话结论

**"输入 → 恰好 3 个方案 → 独立规则校验 → 只放行合法方案"这条链，已用真实适配层与真实规则层端到端证明；
同时找到 9 条规则层产品级问题，其中 2 条会直接伤害用户体验（误杀 + 漏放）。**

## 代码

```
scenarios/
  run_all.py                 总入口：跑全部用例 + 探针，落盘原始输出
  lib/chain.py               链路执行器（intake → 适配 → request → 候选 → 真实规则层）
  lib/scenario_support.py    共享支撑（适配/校验调用、契约化候选构造）
  lib/cases.py               13 个场景 + 4 个边界用例数据
  lib/critique.py            9 条产品级质疑探针
```

## 复跑

```bash
cd <仓库根>
python scenarios/run_all.py          # 全量；末尾有"passed 与 errors 一致性"自检
python scenarios/lib/chain.py        # 官方样例链路冒烟
python scenarios/lib/critique.py     # 只看 9 条质疑探针
```

`run_all.py` 末尾会自检一条不变量：**不存在"passed 却带 errors"或"被拒却出现在可选集合"的候选**。

## 硬约束（本线遵守情况）

| 约束 | 遵守方式 |
| --- | --- |
| **0 次模型调用** | 全程只用 `workflow/intake.py` 与 `validator/rules.py`；真实模型证据取自仓库**既有**产物 |
| **不修改规则层** | 只 `import` 调用 `validator/rules.py`，未改一行；发现的问题写进报告 |
| **候选来源可追溯** | 每个用例带 `source`：`evidence`（既有产物）或 `authored`（人工构造，非模型产出） |
| **不假定双向好感** | 3 个追求对象场景均按"低压力、可被理解为普通朋友往来"设计 |
| **不碰其他线文件** | 只写 `scenarios/**` 与 `docs/scenarios/**` |
| **无 git 分支操作** | 未执行任何 checkout/switch/branch/merge/rebase/push/reset |

## 最值得看的三处

1. **`03-规则层产品级质疑.md` 的 Q8** —— 方案写明"不含酒精"反而被拒。**13 个场景里触发 4 次（31%）**。
2. **同文件 Q7** —— 语义含酒精但标签为 `other`、文本无字面词 → **正常通过**。Q7+Q8 合起来：
   规则门**奖励隐瞒、惩罚披露**。
3. **`02-边界与拒绝场景.md` 的 B04** —— 信息不足时**追问、不生成、不消耗模型调用**。
   这是"产品克制"最硬的证据。
