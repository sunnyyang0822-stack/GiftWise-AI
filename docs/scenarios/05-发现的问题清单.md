# 发现的问题清单（照实写）

> 本文件是场景线"自我批评"的部分。**其中包括我们某些场景其实答不好、以及无法证明的部分。**
> 排序按"对产品承诺的伤害程度"，不按修复难度。

---

## P1 🔴 "选择之后"的四段在整个场景线里是空的

产品定位明确要求：**先三方案与代码校验 → 用户选择 → 选择后才生成详细包装、配色、贺卡与赠送方式。**
13 个场景全部只能走到"选择"为止。**后半段四段（包装 / 配色 / 贺卡 / 赠送方式）整体未实现**
（Web 侧仅有 mock 演示，Dify 侧未接线）。

**为什么排第一**：这不是"没做完的边角"，而是**产品定位的后半段**。
而且它是这份场景报告里唯一**每个场景都缺**的东西 —— 13/13。

**可依据**：`docs/scenarios/evidence/scenarios-raw.json` 每个用例的 `after_selection` 字段，四处均为"未实现"。

## P2 🔴 禁忌规则同时存在"误杀"与"漏放"，且方向相反

| | 表现 | 场景内触发 |
| --- | --- | --- |
| **误杀**（Q8） | 方案写明"不含酒精/无酒"→ 因含字面词被拒 | **13 个场景里 4 个（31%）** |
| **漏放**（Q7） | 语义含酒精但标签为 `other`、文本无字面词 → 通过 | 已复现，真实输出 `status=passed` |

**为什么排第二**：两条合起来，规则门**惩罚披露、奖励隐瞒**。
用户明确说"不要酒"，系统却可能把酒精类礼物放进可选集合；而老老实实声明"不含酒精"的方案反被废掉。

**诚实边界**：这两条都已确定性复现；但在**真实模型输出**上是否触发，本线**无法证明**
（现有真实运行 n=1，且那次模型走了"完全避词"策略，候选原文里禁忌词出现 0 次）。
→ 答辩时应表述为"**已知的确定性缺陷**"，**不要**表述为"真实模型已经踩中"。

## P3 🟠 关系枚举里没有"职场上司"，产品第三优先级关系在代码里无依据

产品定位：`恋人/追求对象` > `朋友` > **`职场上司`**、亲戚家人、同学、老师/导师、客户/合作伙伴。
`workflow/labels.py` 的 10 个关系值里**没有"上司"**（`mentor`=老师/导师，`client_partner`=客户/合作伙伴），
含"上司/领导/老板/上级/主管"的值 **0 个**。

**后果**：前端只能提交 `other`；按 `recipient_relation_id` 分流的产品逻辑（优先级、语气、职场分寸）
对"给上司送礼"**全部不生效**。`colleague`（同事）不能承载它 —— 契约已把同事标注为**仅技术回归**、
不对产品暴露。

**性质**：这是**产品决策**，不是工程 bug。需要产品负责人裁决新增值或明确并入范围。

## P4 🟠 校验之后没有"补位"，可选方案可能少于 3 个

产品承诺"恰好 3 个方案"。但在**刻意覆盖校验分支**的用例里，
**16 个走完校验的用例（13 个场景 + 3 个边界；B04 在适配层终止、不计）中只有 2 个**
拿到了完整的 3 个可选方案（S02、S07）。

⚠️ **必须澄清**：这个比例**不代表真实模型产出** —— 本批用例是我**故意种了违规**才这样的。
真实证据是反过来的：官方样例三案全过；真实 Dify 运行 `v2-run1-demo` 模型产出 **0 违规**。

**仍然要记的问题**：规则层**判得对**，但"判完之后怎么办"没有设计 ——
方案被拒后不解释原因、不补位、不告诉用户"另外 2 个为什么没了"。

---

## P5 🟡 候选金额可以填 0，规则层放行

请求侧禁止 `budget_amount=0`（`LIMIT_EXCEEDED`），候选侧 `estimated_total="0"` **可以通过**。
契约要求"不把未知价格填零"，但这条**只靠模型自觉**。用户可能看到一个"0 元方案"并选中它。

---

## P6 🟡 喜好与禁忌冲突不在输入层提示

`interests=["coffee_food"]` + `hard_exclusions.tags=["food"]` → 适配层 `status=ready`，**零提示**。
矛盾一路带到候选层。若生成侧顺着已确认的兴趣给出三个食品类方案，用户会拿到 **0 个方案**，
且**无法判断是自己的输入矛盾还是系统能力不足**。

---

## P7 🟡 `deadline_days=0` 的成败取决于模型的写法，而不是系统能力

规则层支持 0 天方案（实测 2 个通过）。但若模型习惯性写 1–2 天准备期，
**最急的用户会拿到 0 个方案**，而系统不会提示"把准备期改成 0 天即可"。
→ 需要生成侧提示词约束，规则层无法补救。

---

## P8 🟡 场景里的所有金额都是估算，不是实时价格

本报告里所有 `estimated_total` 都是**估算值**，`business_data_verification` 恒为 `not_verified`。
真实价格/库存/物流**均未核实**。
→ 场景走查能证明"金额约束被执行"，**不能**证明"报价是真的"。答辩时不要混为一谈。

---

## P9 ⚪ 我们还没能证明的：真实模型是否会触发那条误杀

现有**真实模型输出样本只有 1 次**（`v2-run1-demo`，1514 tokens，禁忌词"巧克力"），
而那次模型**完全避开了禁忌词**（候选原文 1309 字符里"巧克力"出现 0 次）。
→ 所以"Q8 误杀在真实输出上的触发率"是**未知**的。

**要补这个洞需要什么**：一次真实模型运行，且**用"酒/酒精"作禁忌词**、
并观察模型是否会在文案里写"不含酒精"这类声明。
**本线没有做这件事** —— 因为要守住"不消耗 Dify 额度给 11-01 现场 Demo"这条硬约束。
如果有一次富余额度可用，这是**最值得花的一次调用**（它能把 P2 从"潜伏缺陷"升级为"已证实缺陷"或"已证伪"）。

---

## P10 ⚪ 本线验证的是"规则层端到端"，不是"全栈端到端"

- 本线走的是：intake 原文 → 适配层 → request → **人工构造的候选** → 真实规则层。
- **中间那一步（真实 Dify 生成三候选）本线没有跑** —— 0 次模型调用。
- Web 前端跑的是 **mock**，本轮也没有做真实模型 ↔ 界面的端到端验证。
→ 所以准确表述是"**输入 → 规则校验 → 只放行合法方案**这条链已端到端证明"，
**不是**"整个产品端到端已证明"。

## 附：本线**没有**发现问题的部分（同样是结论）

为避免只报坏消息造成误判，以下是**经过验证、表现良好**的部分：

1. **金额、准备期、币种三类硬约束拦得准**，且**不连坐**（只拒违规的那一条）。
2. **`DUPLICATE_CANDIDATE_CONTENT` 有效** —— "三个同义词"被真正挡住（S08）。
3. **`UNKNOWN_FACT_REF` 有效** —— 模型无法编造事实依据（S11）；这是"禁止无依据推断"最硬的一条机器约束。
4. **`UNKNOWN_TAG` 有效** —— 候选不能自定义类别绕过禁忌检查（S09）。
5. **信息不足时追问而不是硬给方案**，且在适配层终止、**不消耗模型调用**（B04）。
6. **规则层是纯函数**，可离线复跑、不联网、不读环境变量。
7. **真实模型产出能被规则放行**（官方样例三案全过；真实运行 0 违规）—— 规则不是"只会拒"。
