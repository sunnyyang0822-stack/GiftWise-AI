## 主张 3：三方案必须**恰好三个**，且互不重复

**怎么验**：给规则层 2 个或 4 个候选 → `INVALID_CANDIDATE_COUNT`；
给两个名称+描述标准化后相同的候选 → `DUPLICATE_CANDIDATE_CONTENT`。

```bash
python scenarios/run_all.py          # 跑全部 17 个用例 + 9 条质疑探针
```

**实测**：场景 S08 的两个"精品咖啡豆订阅一个月"（名称与描述完全一致）**同时被拒**
（`DUPLICATE_CANDIDATE_CONTENT`），只剩 1 个方案可选。
→ 这条规则直接回应了产品负责人"不能是三个同义词"的要求。

**原始输出**：`docs/scenarios/evidence/scenarios-raw.json` → `scenarios[7].candidate`。

## 主张 4：**只有通过校验的方案才进入用户的可选集合**

这是"独立规则校验"这件事的核心价值。**怎么验**：

```bash
python -c "
import json,sys; sys.path.insert(0,'.')
sys.path.insert(0,'scenarios/lib')
from scenario_support import build_request,call_validate,cand,batch,INTAKE_BASE
rq,_=build_request(dict(INTAKE_BASE, budget_amount='50.00'))
res=call_validate(rq,batch(
  cand('c1','低价方案','以低价小物为方向。','45.00',1,['other'],'在预算内。'),
  cand('c2','超预算方案','以高价礼盒为方向。','500.00',1,['other'],'超出预算。'),
  cand('c3','时间不够方案','以定制物品为方向。','40.00',99,['other'],'准备期过长。')))
print(res['status'], res['all_passed'])
for c in res['candidate_results']:
    print(c['id'], c['passed'], [e['code'] for e in c['errors']])
"
```

**实测**：`status = failed`、`all_passed = False`；`c1 passed=True`；`c2` 报 `OVER_BUDGET`；
`c3` 报 `PREPARATION_TOO_LONG`。**两个不合法方案不进入可选集合。**
自检脚本另有一条不变量检查：**没有任何"passed 却带 errors"或"被拒却出现在可选集合"的候选**
（`scenarios/run_all.py` 末尾自检输出"全部一致 ✅"）。

## 主张 7：越界输入被**请求层**挡住，而不是靠模型自觉

预算与准备天数有明确范围（`[1,10000]`、`[0,365]`），越界走请求层 `LIMIT_EXCEEDED`：

```bash
python -c "
import json,sys; sys.path.insert(0,'.')
from workflow.intake import adapt_intake
base=json.load(open('workflow/examples/intake.json',encoding='utf-8'))
for k,v in (('budget_amount','0'),('budget_amount','10001'),('deadline_days',366)):
    i=dict(base); i[k]=v
    r=adapt_intake(json.dumps(i,ensure_ascii=False))
    print(k,repr(v),'→',r['status'],[e['code'] for e in r['errors']])
"
```

**实测**：三者均 `needs_input` + `LIMIT_EXCEEDED`。
