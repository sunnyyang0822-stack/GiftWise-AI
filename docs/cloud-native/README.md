## 一句话结论

> **交付物已经容器化，但还没有云原生化。**
> 真正阻塞上云的是三件事：**每请求 90.5% 的 CPU 花在 HTTP 框架上**（不是业务逻辑）、
> **`/healthz` 探针会在服务已经退化时全绿**、**进程不支持优雅停机（滚动更新必丢在途请求）**。
> 因此本线的建议是：**先修这三件事，再谈上云；现在上 K8S 属于过度设计。**

## 诚实性边界（最重要的一节）

本线所有结论都刻意贴着证据写。**宁可少说，不可说过。**

### 已实测（有原始输出，在 `compose/evidence/`）

- 镜像事实：`d9a4a35763ee…`、177,918,474 B、`CMD ["python","-m","deploy.server"]`、uid 10001；
- 冷启动到 `/healthz` 200：**0.714~0.823 s（本线自测口径）｜交付镜像 **0.668 s**（均值）**（本线自测 3 次）；
- 常驻内存：cgroup **19.03~20.89 MiB** / `docker stats` **15.27~17.02 MiB**；
- 60 请求轮询分发 **30/30**，两副本都被用到，60/60 `passed`；
- **同一会话跨两个副本**（会话语义**不**保持）；
- HTTP/1.0 响应后关闭，同 socket 第二请求收 **0 字节**；
- 失败转移代价 **1273.965 / 1280.862 ms**（正常 4~5 ms，**约 250 倍**）；探测发现耗时 **5.97 s**；
- 半开正文挂 **10.012~10.014 s** 期间 `/healthz` **27/27 全绿**；
- 默认入口 `/metrics` **404**；可观测入口匿名与伪造 Basic 均 **200**；
- 40 请求多副本下每副本各报 **20**（无副本知道总数 40）；
- 每请求服务端 CPU **1794.35 us**，其中 `validate()` 仅 **170.87 us = 9.5%**；
- 日志驱动只影响 **1.2%**（`--log-driver none` vs `jsonfile`）；
- 2 副本/1 副本吞吐增益 **0.89~1.23x**（≈1x，**扩容收益测不出来**）。

### 明确标注为「推断」（无实测支撑）

- 单机 ~1030 ms 尾延迟台阶归因于**宿主↔WSL2 端口转发**（现象已测，归因是推断）；
- 健康探测随上游数**线性变慢**（只测了 2 个上游）；
- 跨主机场景下**无 keep-alive 的代价会显著上升**（无跨主机环境）；
- **backlog 5→512 能减少 48 并发丢包**（交付镜像用默认 5；未测新版本）；
- GIL 是当前吞吐上限的直接原因（未做多进程对照）。

### 明确「未做 / 做不到」

1. **未在 UCloud 或任何公有云执行；未采购主机/EIP；未推送镜像仓库。**
2. 未做多主机实验 → **所有吞吐/延迟数字不可外推到云端**。
3. 未应用优雅停机补丁（`deploy/**` 是禁区）→ 补丁**运行时行为未验证**，
   只验证了「能干净套用 + 套用后语法正确」。
4. `compose/k8s/` 的 YAML **从未 apply**，也**未经过 API server schema 校验**（只做了 YAML 语法解析）。
5. 未审计 Dify 侧密钥管理（无权限，且不允许消耗额度）。
6. 未做长时间稳定性/内存泄漏测试（单次最长负载 20 s）。
7. 未做合规/安全审查。

### 一处必须知道的方法学坑（本线踩过并修正）

`docker exec` 会给**目标容器** cgroup 记上约 **17~21 ms** CPU。
因此「两次 exec 夹一段 sleep 测空转 CPU」的方法**必然**失败——
本线的第一版日志实验据此得出「日志占 34.9%」的**错误结论**，已撤回并修正为 **1.2%**。
完整修正过程保留在 [`../../compose/evidence/logdriver-vs-none.md`](../../compose/evidence/logdriver-vs-none.md)。

## 可复跑性

- **LB 是纯 Python 标准库**（`http.server` + `http.client`），刻意**不用 nginx**
  （环境没有、装不了、会引入评委无法复现的依赖）。
- 所有实验脚本在 `compose/` 下，原始输出在 `compose/evidence/` 下。
- 复跑前请先读 `02-本地模拟实验.md` 第 0 节的**环境注意事项**
  （`docker` 不在 bash PATH、MSYS 路径改写、必须用 `perf_counter` 而非 `monotonic`）。
- 清理请用**同一组 `-f` 参数**加 `--remove-orphans`，否则会留下孤儿容器（见 00 号文档）。
