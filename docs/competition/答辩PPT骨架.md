## 第 1 页 · 项目概述：解决什么问题，最终做出了什么

## 第 3 页 · 整体方案与选型理由

**标题**：整体方案：模型生成 + 独立校验 + 服务端可信状态

**页面要点**

- 三个关键设计决定：
  1. **生成与判定分离**：模型只负责"有依据的方向"；预算/币种/禁忌/必填/准备时间由**独立 Python 代码**判定。
  2. **用户选择在中间**：未选择前**不生成**任何详细包装/贺卡（避免一次性生成三份浪费且有诱导）。
  3. **状态在服务端**：浏览器只提交输入与选择，**不信任**前端传来的 `passed` 标记。
- 选型与理由（含替代方案与代价）：

| 技术 | 用途 | 选它的理由 | 代价/替代 |
| --- | --- | --- | --- |
| Python 3.12（**纯标准库**） | 确定性规则 | 零第三方依赖，评委可二次复验；容器内**逐字节一致** | 需自己实现；已用 `re.ASCII`+NFKC 防全角绕过 |
| Dify Cloud 1.18.0 | 模型编排 + Code 节点 | 平台承担编排、节点调度与沙箱 | 平台耦合；**ELSE 分支无运行证据**；**trace 不可用** |
| DeepSeek 模型节点 | N2 生成 / N5 修订 | **真实调用已跑通**，token 可由服务端采集 | **用户自备额度；单价未核实** |
| Node.js（**零依赖**） | 中文页面 + 薄接入层 | 无需构建工具链，本地即可演示 | 无框架；**无性能数据、未在真实浏览器验证** |
| Docker（**本机实测**） | 可复现打包 | 178 MB；**冷 2.2 s／热 0.6 s**；**9/9 项通过** | **未推镜像仓库、未上云；单机基线≠生产容量** |

- 为什么**不**做：不做微服务、不上 K8s、不引数据库 —— **云部署从未发生**，当前无任何容量证据支撑这些复杂度。

**口播稿（约 38 秒）**

> "核心判断是：模型可以给建议，但不能给自己打分，所以硬约束全部交给独立 Python 代码，这份规则只有一份真源，同时喂给 Dify 的 Code 节点、本地 API 和容器。第二个决定是让用户在中途做选择。第三个是把可信状态放在服务端。容器我们只做了本机实测与可复现打包，明确没有上云、没有 K8s——本机容器数据是单机基线，不是生产容量结论。"

## 第 6 页 · 工程化设计（复现、异常处理、可靠性、可观测性）

**标题**：工程化：复现、异常处理与可观测性

**页面要点 — 复现**

- **零第三方依赖**：`validator/`、`workflow/`、`deploy/` 只用 Python 标准库；`web/` 只用 Node 内置模块（`dependencies` 为空）→ 无需 `pip install` / `npm install`。
- 生成物带 `sources_sha256` / `artifacts_sha256` 哈希清单，**逐一匹配**；`/healthz` 返回规则源码哈希 → 可确认现场运行的就是提交版本（**A4**）。
- 容器 `/validate` 与本机**逐字节一致**（**A4**）；镜像内**无密钥**、以**非 root（uid 10001）**运行（**A5**）。
- `deploy/server.py` **状态码矩阵**与进程内调用一致（**A7**）。
- **B 未完成**：镜像未推仓库、未上云。

**页面要点 — 异常处理**

| 异常 | 处理方式 | 状态 |
| --- | --- | --- |
| 模型输出损坏 JSON | 真实被判可修订 → 一次修订 → 重检通过（case4） | **A** 真实运行 |
| 持续失败 | 真实复现 `all_passed=false`、`repairable=false`，**如实失败不伪装**（case5） | **A** 真实运行 |
| 硬约束不满足 | 失败项**不可选**；首次错误码均为 `FORBIDDEN_TERM` | **A** 真实链路 |
| 未选择就请求呈现 | `INVALID_SELECTION`，**不替用户选择** | **A**（接入层） |
| 伪造/越界的候选或状态 | 服务端按运行 ID + 候选版本校验；不信任前端 `passed` | **A**（接入层） |
| 容器错误路径 | 非法 JSON / 载荷类型错误 / 未知路径 / 无 `Content-Length` / 超长体 **全部符合契约** | **A** 容器实测 |
| **B9** 提示词修复**之后**的修复路径（真实修订→再校验） | **没有运行时证据** | **B** 未完成 |
| 工具调用失败 / 超时 | 中文提示、不重试风暴；**独立成文的异常处理说明尚未完成**（G-3） | **B** 未完成 |

**页面要点 — 可靠性与可观测性**

- 服务端持有：运行 ID、候选版本、两次校验输出、**全局修订计数**、错误码、调用计数。
- **token 取服务端 `workflow_finished.total_tokens`**（**34,127**）。
- 接入层语义一致 **55 组 / 0 差异**；HTTP 冒烟 **59 项 / 0 失败**（**A6**）。
- **B 未完成**：**B6** 平台级 trace 不可用（`not_collected`），无平台侧调用链；**B14** 阶段 14 采集方案仍是设计；**B15** `web/` 无性能数据、未在真实浏览器验证渲染与交互；**B16** parity 仅样例级等价、无安全专项测试（注入/越权/限流）；**B17** 提交为临时提交、未独立评审（PM 工具不入库）；**B12** DeepSeek 单价未从真实账单核实。

**口播稿（约 38 秒）**

> "工程化三点。第一复现：没有第三方依赖，生成物带哈希，健康检查返回规则源码哈希，容器里的校验结果与本机逐字节一致，镜像里无密钥且以非 root 运行。第二异常处理：模型输出损坏 JSON 和持续失败都有真实运行证据，原则是失败就是失败；但提示词修复之后的修订路径还没有运行时证据。第三可观测性：token 从服务端 total_tokens 采集，语义一致性与 HTTP 冒烟都通过了；但平台级 trace 不可用，阶段 14 采集仍是设计，前端没有性能数据也没有在真实浏览器验证，parity 只是样例级等价且没有安全专项测试，提交也还是临时提交。"

## 第 7 页 · 成本、性能与取舍
