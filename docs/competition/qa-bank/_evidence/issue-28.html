QA-BANK-001｜评委问答库（7 分钟 Q&A）

  • 提出：PM Agent｜2026-10-31
  • 关联：产品定位与 MVP 体验：所有协作 Agent 的统一依据 #1 产品定位、ARCH-001：阶段 3 技术方案设计——把赛道 B 评分规则映射到架构、异常处理与可观测性 #5 架构、CONTRACT-001：阶段 4/5 数据模型与 API 契约冻结（含新增 pursuit 关系值） #6 契约、DEMO-001：阶段 13 上线/Demo 冻结骨架——README、PPT、演示脚本与材料清单 #9 发布与答辩、RESEARCH-001｜商品价格数据来源技术调研：我们到底能不能拿到真实价格 #26 价格调研
  • 性质：答辩准备，不新增功能、不改实现

为什么开这条线

答辩含 7 分钟 Q&A。评委最可能问的恰恰是我们最弱的地方（价格真实性、为什么不上 K8S、
四段呈现是真是假）。提前写不出答案，现场就会含糊；含糊一次，前面 5 分钟报告的可信度就掉了。

文件边界

  • 可写：docs/competition/qa-bank/**（新建目录，本线独占；PM 已与发布线约定该子目录归本线）
  • 只读：仓库内其他一切文件
  • 不要动：docs/competition/ 下的现有文件（材料清单与自查.md、答辩PPT骨架.md、
    架构图-GiftWise.png、答辩PPT-GiftWise.pptx、评分规则原文）

任务：不少于 20 条问答，覆盖以下 10 类

  1. 产品定位与差异化：跟"直接问 ChatGPT 要礼物建议"到底差在哪？关系优先级怎么定的？
  2. 价格与库存真实性（最可能被追问）：你们的价格是哪来的？为什么说"未核实"还能推荐？
  3. 架构选型：为什么不上 K8S / 不做微服务 / 不做多副本？单镜像 + 单进程凭什么算"云原生"？
  4. 成本与性能：单任务成本多少？并发能力多少？（实测的说实测，unknown 就说 unknown，绝不许填 0）
  5. 工程化：测试规模（322→329）、39/39 阶段 C、46 探针、parity 多少组、容器检查多少项
  6. 合规与隐私：API key 放哪？用户数据怎么处理？公开内容是否只用虚构人物与脱敏数据？
  7. 四段呈现（包装/配色/贺卡/赠送方式）是 mock —— 必须准备好如何承认，以及为什么仍然值得做
  8. Dify 已发布并创建版本，但发布后应用的外部可访问性未核实 —— 要能说清这句话的边界
  9. Dify 工作流内嵌的是规则源码的"快照"：源码再改动需重新发布才能同步（这是诚实的技术细节）
  10. 压力追问：每条再准备"追问 1 / 追问 2"，尤其是"那你为什么不直接买 API？""没有真实数据凭什么说更懂用户？"

每条格式（缺一不可）

### Q：<问题>
- **一句话答案**：
- **证据位置**：<命令 / 文件:行号 / 证据目录>
- **必须承认的边界**：<这条我们没做到什么>

硬要求

  • 每个答案都要能追到证据（命令或文件）。追不到的，写"未核实"并说明为什么现在核不了。
  • 禁止编造任何数字。数字必须来自仓库里的实测证据，且注明出处。
  • 需要外部信息的问题（例如"真实价格能不能拿到"），只能引用 RESEARCH-001｜商品价格数据来源技术调研：我们到底能不能拿到真实价格 #26 调研的结论；RESEARCH-001｜商品价格数据来源技术调研：我们到底能不能拿到真实价格 #26 未出结论前写"调研进行中"。
  • 答案要短：一句话能说完就一句话（现场是口头回答，不是念文档）。

交付物

  1. docs/competition/qa-bank/评委问答-2026-10-31.md（≥20 条，按上述格式）
  2. docs/competition/qa-bank/README.md，含 "高风险问题 TOP 10"（按"答不好就丢分"排序）
  3. docs/competition/qa-bank/未核实清单.md：所有我们答不上来、只能承认的问题，逐条列出

零模型调用。
