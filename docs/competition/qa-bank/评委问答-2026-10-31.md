## ① 产品定位与差异化

### Q1：你们跟「直接问 ChatGPT 要礼物建议」到底差在哪？

- **一句话答案**：差在**模型之外**——模型产出三个候选后，必须过一遍**与模型无关的代码校验**（预算、天数、禁忌、关系契约），再由用户明确选择；模型不能直接把结果交给用户。
- **证据位置**：`AGENTS.md`（先三方案+代码校验→用户选择→才生成详细内容）；`docs/architecture/adr/ADR-001-rules-inline-not-microservice.md`（规则与模型独立，SC-3）；`docs/intake-contract.md:15`
- **必须承认的边界**：这个差异化在**推荐阶段**成立；**选择之后的呈现阶段我们没有实现**（Dify 侧未接线，网页侧是 mock）。
- **追问 1**：那不就是加了个校验？→ 校验是唯一能拦住"超预算／送酒"的东西，模型自己不保证不越界，这是 SC-3 的全部意义。
- **追问 2**：ChatGPT 也能反问问清需求。→ 我们把它固化成**契约**：8 个关系 ID 冻结、`pursuit` 与 `partner` 互斥、关系分支按机器值判断，可被代码检验，不靠聊天记忆。

### Q2：关系优先级是怎么定的？谁定的？

- **一句话答案**：**产品负责人拍板**，产品面冻结 **8 个稳定关系 ID**；`pursuit`（追求对象）与 `partner`（恋人）**并列互斥、不得合并**；`colleague`（同事）**仅技术回归**，不对产品暴露。
- **证据位置**：`docs/intake-contract.md:15`、`:167`；`workflow/labels.py`；实测 `node web/tools/parity-check.mjs` → **74 组**样例 0 处差异（**10-30 旧口径 55 组**）
- **必须承认的边界**：`colleague` 仍留在代码枚举与一个**技术回归夹具**里（`workflow/examples/intake-colleague.json`，仅回归，**不得出现在产品面/界面/演示/验收**）；`docs/demo-script.md` 首场景**已改为「追求对象／恋人」**（原"首场景是同事"的缺陷**已修**，本轮复核 `docs/demo-script.md:7`）。
- **追问 1**：为什么追求对象要单列？→ 追求关系**不能假定已有恋爱关系或双向好感**，语气、花材、赠送场合都要更克制，混进 `partner` 会给出越界建议。
- **追问 2**：中文"对象"分不清怎么办？→ 契约只认机器值 `pursuit`／`partner`（`recipient_relation_id`），中文文案由 `labels.py` 映射，代码分支不看中文。

### Q3：为什么全局只允许**一次**自动修订？

- **一句话答案**：防止"改到通过为止"——那会把成本和延迟放大，也会把失败伪装成成功；**一次改不好就如实报失败**。
- **证据位置**：`workflow/evidence/WF-003-2026-10-30.md` §4.5（R1：真实违规→真实修订→**通过**；R2：修订后仍不通过→`failed`、`repairable=false`，只放行 c2/c3）
- **必须承认的边界**：真实模型下**自然触发超预算修订**的运行时证据**仍没有**（超预算→修订的完整链路只有占位期注入证据）；`FORBIDDEN_TAG` 标签级禁忌也未自然触发。
- **追问 1**：那怎么保证质量？→ 不保证"更好"，只保证**不越界**：超预算、禁忌、天数硬拒，失败状态如实返回。
- **追问 2**：用户手动要求再改一次呢？→ 全局上限一次且**不可由前端重置**；当前可信修订计数由输入提供、**不是防篡改机制**（真实缺口）。

## ② 价格与库存真实性（最可能被追问）

### Q4：你们推荐里的价格是哪来的？

- **一句话答案**：**目前没有任何真实价格**——候选里的价格是**估算**，并且字段旁就写着"实际价格、库存和送达均未核实"。
- **证据位置**：`web/server/mock-model.mjs:42`、`:54`（`unknowns` 文案逐字）；`docs/product-data-research.md` 首段（**未开通商品 API、未核验真实商品报价、未实现集成**）
- **必须承认的边界**：我们没有接入任何商品数据源；价格**不可结算、不保证库存、不保证送达**。
- **追问 1**：那你们页面上的数字是编的？→ 是**估算**并已标注未核实，不是抓取结果；我们从不把它标成实时价。
- **追问 2**：有没有一条真价格？→ 有一条**调研样例**：公开页面 KINTO `SCS-S03 手做陶瓷马克杯 320ml` 标价 ￥168.00，但那只证明"某已知页面可提取"，**不是**自动搜索命中，也不证明结算价。

### Q5：既然自己写"未核实"，凭什么还能给出推荐？

- **一句话答案**：我们推荐的是**送礼思路与关系适配**，不是报价单；预算是拿"估算总价"做**算术与禁忌硬校验**，超了就拒。
- **证据位置**：`validator/rules.py` + `deploy/server.py` 的 `/validate`（预算/天数/禁忌）；`docs/architecture/cost-performance-metrics.md`（规则 p50 0.166 ms）
- **必须承认的边界**：**估算不等于报价**。如果评分要求"三件可立即购买、价格精确"，我们**当前证据不支持**，不能声称做到。
- **追问 1**：那用户看到价格会不会误以为能买？→ 所以我们在候选与呈现里都写 `unknowns`，并区分"信息来源"与"购买入口"。
- **追问 2**：超预算会不会算错？→ 预算是纯函数算术并有用例覆盖；但**估算本身可能失真**，这是我们承认的输入质量问题。

### Q6：一天之内能把真实价格接进来吗？（#26）

- **一句话答案**：**#26 的结论是没有通过**——实测了 Tavily（免 Key 可搜索并可读部分中文商品页）与 Firecrawl（无 Key 被 403 拒绝），结论是"**无需人工整理、一天内稳定返回三种符合预算的具体商品与价格**"**尚未验证通过**。
- **证据位置**：`docs/research-evidence/product-data-probe/README.md:7-9`、`:36-48`、`:84`；`docs/product-data-research.md` 首段与"结论"节
- **必须承认的边界**：14 次取得 HTTP 响应的调用里，多条中文长查询**偏题**（混入新闻/台币商品/加密内容），京东列表页**未取得可用标价**，沿链接读详情 **2/2 失败**；本轮**未注册账号、未付费、未使用任何 API Key**。
- **追问 1**：那为什么不直接买京东/淘宝 API？→ 见 Q24：审批与商务不在本次窗口内，#26 明确写"未开通"；我们也没谎称已开通。
- **追问 2**：Tavily 免 Key 不是能用吗？→ 能"验证"，官方免 Key 有隐式限流且**本次未确认上限**；正式 Key 免费档为每月 1,000 积分，**调用次数≠积分**，不能当作产品唯一依赖。

## ③ 架构选型

### Q7：为什么不上 K8S？

- **一句话答案**：当前是**单用户、低频、会话式**负载且**真实并发未知**，上 K8S 只能换来编排、网络、镜像仓库、密钥与运维成本，**没有任何已验证的容量收益**可以交换；评分规则要的是"**能解释取舍**"。
- **证据位置**：`docs/architecture/adr/ADR-003-cloud-native-tradeoffs.md`（决策表 + 理由第 1 条）；负载约束 `docs/architecture.md` §8.1
- **必须承认的边界**：因此**弹性伸缩、资源调度、分布式状态三项都没有**；且**主办方是否强制容器/K8S 我们尚未核实**（该 ADR 第 5 条已列）。
- **追问 1**：那你们算云原生吗？→ **不声称**。我们只声称：容器化已实测（本机单实例）、云部署从未发生。
- **追问 2**：给足时间会怎么演进？→ 先补**分布式状态**（现在进程内存、重启即丢、多副本不可用），再谈编排——顺序不能反。

### Q8：为什么规则不做成微服务？

- **一句话答案**：规则是 **0.166 ms 的纯函数**，拆成远程服务会把延迟推到 **12.5 ms 量级**（本机回环实测）并引入网络故障面，**换不到任何好处**。
- **证据位置**：`ADR-001`（背景/决策/理由）；`docs/architecture/cost-performance-metrics.md`（p50 0.166 ms vs HTTP 往返 p50 12.545 ms）
- **必须承认的边界**：代价是**同一语义有多份实现**（Python 权威 + JS 镜像 + Dify 内嵌快照），一致性靠 parity 用例与哈希，**不是编译期保证**。
- **追问 1**：多份实现不会漂移吗？→ 会，这正是最真实的长期风险；目前用 **74 组** parity 0 差异（**10-30 旧口径 55 组**）+ 5 个内嵌 code 的 sha256 逐项对照来兜。
- **追问 2**：那独立规则 API 为什么还留着？→ 保留**可运行、已容器化**的实现作为条件性能力（评委可复验），但**不在关键路径**上。

### Q9：单镜像 + 单进程，凭什么算"云原生"？

- **一句话答案**：**我们不说它算**——容器化只做到"本机单实例、可复现打包、可复验"；**云部署从未发生**。
- **证据位置**：`deploy/evidence/docker-2026-10-30.md`（D-0…D-13 全通过 + 口径声明："容器只绑定 `127.0.0.1`，未对外暴露；未上传任何 registry；未产生云资源费用"）
- **必须承认的边界**：无云主机、无 EIP、无镜像仓库推送、无多副本、无编排、无弹性伸缩；**`publish-to-uhost.ps1` 从未执行**。
- **追问 1**：那容器化对评分有什么用？→ 它证明"**别人能复验**"：14 项检查、交付镜像 **169.676 MiB**（177,918,474 B；**构建时基线 169.36 MiB** 已作废）、`/validate` 与本机纯函数逐字节一致。
- **追问 2**：镜像 ID 能作为判据吗？→ **不能**：同内容三次重建得到三个 ID（`b42f408b4f07`／`61bdb8815bd9`／`ed3fbe912571`）；判据应用基础镜像 digest、`/healthz` 的规则哈希与字节数。

## ④ 成本与性能（unknown 就说 unknown）

### Q10：单任务成本是多少？

- **一句话答案**：**金额成本未核实**——token 有服务端依据，但**没有供应商真实账单**，我们不按公开牌价推算、也**不填 0**。
- **证据位置**：`workflow/evidence/WF-003-2026-10-31-publish-v2/README.md` §0（累计 **13/16 次、38,326 tokens**）；`docs/architecture/cost-performance-metrics.md`（金额成本记 `not_measured`）
- **必须承认的边界**：**单价、试用额度余额、单任务人民币成本全部 unknown**；而且这些额度是**用户自备 Key**，不是我们代付。

- **追问 2**：token 会不会失控？→ 有硬上限：**16 次调用**封顶，当前用掉 13 次，跑完即停、无自动重试。

### Q11：并发能力多少？

- **一句话答案**：**unknown**——我们**没有做过任何并发测试**，所有性能数字都是**串行单进程**。
- **证据位置**：`docs/architecture/cost-performance-metrics.md`（"并发容量与限流阈值仍未知"）；本地测量口径 n=200、每请求新建连接、串行
- **必须承认的边界**：容器侧只有 **5 次串行启停**样本；`deploy/server.py` **未设任何 socket 超时**（**这句仍然成立**：I-2 的修复用的是**读请求体的总时长预算**，不等于给 socket 设超时），已登记缺陷 **I-2** **已于 2026-10-31 01:13:59 修复并随交付镜像生效**（见 Q23 与《未核实清单》）。

- **追问 2**：上多副本行不行？→ 不行：可信快照在**进程内存**，多副本不共享状态，这是必须先补的缺口。

### Q12：延迟到底是多少？

- **一句话答案**：分段实测——规则 p50 **0.166 ms**、无模型端到端 p50 **0.640 ms**、回环 HTTP p50 **12.545 ms**；真实模型段 N2 **4.5–6.0 s**、N5 **3.0–3.1 s**、工作流端到端（含 7 个 Code 节点）**5.2–8.9 s**。

- **必须承认的边界**：**浏览器端到端延迟从未测过**（网页接入层未接真实模型）；以上全部是单用户串行，**不是并发性能**。
- **追问 1**：瓶颈在哪？→ 模型生成段，不是规则层（规则 p50 0.166 ms，比模型快 4 个数量级）。
- **追问 2**：还有一条 0.587–0.888 s 的服务端耗时呢？→ 那是**注入轮（无模型）**的 Dify 服务端耗时，**不能当作业务延迟**读。
