展示“送什么 → 为什么适合 → 横向比较 → 用户选择”；独立规则用一条失败路径说明作用，自动修订不占主场景。正式演示以现场真实运行为主，录屏只作故障备用或外部依赖佐证，不能代替所有可现场验证核心功能。

QA 未锁版时，只可作标注清楚的文案走读，不按下表声称已有画面。锁版后 PM 需在本文件登记：交付 commit、契约版本、实际运行模式、前端/接口/规则的证据、真实模型联调范围、屏幕入口和回退路径。任何模式只写真实值，不预设已可在线运行。

## 虚构主案例

关系：追求对象，正在相互了解；不假定对方有好感。已知喜欢阅读、常做笔记；简洁风格只是送礼者推断；现有用品、是否接受礼卡未知。预算和准备时间在锁版演示时按 QA 已验收夹具填写，本稿不编造实际价格与准备工期。

人工示例候选为阅读笔记本、书店礼卡、书签，仅用于讲解比较思路。现场使用 QA 锁版后的实际候选输出，不承诺模型恰好生成这些名称。

## 三分钟逐段文案与动作（设计预算）

| 时间 | 话术 | QA 锁版后操作 / 观察点 |
|---|---|---|
| 0:00–0:20 | “今天帮小林给正在了解中的小禾挑礼物。喜欢阅读是已知，是否已有同类用品未知；追求关系不代表对方已接受。先说明这次演示的版本与模式……” | 显示版本与模式；口头补齐真实状态，不填想当然结论 |
| 0:20–0:45 | “先填知道的信息、礼物预算和准备时间，不确定的保留未知。不喜欢的内容需要正确理解并确认，不能悄悄忽略。” | 仅操作已验收输入。新版滑条、识别确认、时间映射未验收时不得当成已完成动作；此段暂停待 QA，不临时切旧输入冒充 |
| 0:45–1:40 | “现在重点看三个方向。这个与已知习惯有什么联系？哪个理由是推断？哪些信息仍然未知？我们用同样维度比较，才知道该取舍什么。” | 横向阅读实际三候选、理由、事实/推断/未知、礼物估价与准备时间；人工稿与运行结果不能混用；不在此展开错误码 |
| 1:40–2:05 | “比较前还有一道可信保障：超出预算或碰到已确认禁忌，不能当成合格方案。这里仅展示一条经过验收的失败路径；最多一次修订是兜底，失败仍明确说明。” | QA 选择已锁版的真实拒绝案例；说清本地规则、mock 注入或真实模型的来源，不能把人工构造输入说成模型自然违规 |
| 2:05–2:40 | “我根据对方的记录习惯，选择这个已经通过检查的方向。只有选定后，才围绕这一份礼物补充配色、贺卡和赠送方式。” | 可信选择事件与选后增强/账单，全部待 QA 后启用。未验收只解释目标并明确不展示成功账单，不跨接旧 mock |
| 2:40–3:00 | “最终决定仍由用户做。系统帮忙说明适合的依据与不确定性；价格、库存、物流未核实，不能保证对方喜欢。新版完成范围以本次版本验收单为准。” | 停在真实已验收结果或明确限制页，未通过不展示为完成。收束回礼物选择 |

## 预算和识别的固定说法（产品要求，不是完成声明）

礼物预算只计所选礼物本身，三候选不相加；包装仅建议风格色调且不报价，贺卡、装饰、配送也不计入礼物预算，不等于免费。零支出意为礼物本身不新增支出，材料若需新购不可说免费。准备时间档位必须显示映射，不是送达承诺。

语义识别只提出有原文依据的排除项，经用户同页确认、服务端固定后由规则拦截；锚定原文不证明语义正确。无法可靠理解或未完整确认时要先澄清。新版识别与真实模型路径待验收。

## 故障处置

发生超时或依赖失败时，用该版本实际中文错误解释原因，保留已填信息的能力也须经 QA 确认。停止重复点击，不等待未经测量的固定秒数，不无限重试；下一段或 B 模式仅按 PM 锁定的方案切换。没有归档证据就直接说该段未能演示，不用模拟成功补洞。

删减优先级：先省选后增强细节，再省规则案例解释；保留三方案、理由比较、用户选择和真实性声明。最终真人计时、屏幕入口、具体失败夹具、等待阈值与截图，均由 QA 锁版后回填。
