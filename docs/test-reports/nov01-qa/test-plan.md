状态：第一波测试设计；等待规则、AI、接入与前端 PR 集成后执行。本文不是新版已通过证明。

## 依据与边界

验收依据为 Issue #1 的 2026-10-31 增量确认、`docs/design/交付变更契约-2026-10-31.md` 和 `docs/pm-reviews/三份设计稿审查-2026-10-31.md`。所有公开夹具均为虚构资料。识别、Dify、线上模型、价格库存物流和云部署在未提供真实运行证据前记为未测；mock 只能证明固定路径。

本线只新增 `tests/acceptance/nov01_revision/` 与本报告目录；不改规则基线、业务代码、历史报告或 `tests/test_cases.json` / `tests/test_validator.py`。

## 分层执行顺序

1. 先执行夹具自检，确认案例数量、独立零元/区间/旧标量期望、虚构数据和 Python 语法。
2. 集成后分别执行旧基线：tests 329、stage_b 275、stage_c 39、boundary 45；这些数字只作实际运行结果，不能用 discover 通过替代断言。
3. 执行新增规则套件并记录每组 `status/all_passed/error code/path/warnings`。特别检查 0 元+366 天仍拒绝，低于区间下限只产生 warning，三个候选不加总。
4. 更新 parity 生成器后，在临时目录生成 fixture；独立断言零元、区间、金额格式和六档天数期望，再比较 Python/JS 的结构、错误码、路径、中文文案和 warnings。两侧一致不视为正确性证明；`days=10**20` 残差照实登记。
5. 接入服务在本线专用端口先 `GET /healthz`，核实服务身份与 `mode`，显式设置 `GW_BASE` 后再跑 HTTP 冒烟。浏览器仅使用项目专用配置；若没有浏览器依赖，结果为阻塞而不是安装依赖或推断通过。
6. 真实模型、Dify、新版线上能力和镜像一致性分别写 `未测`，不从旧报告继承新版结论。`tools/verify_all.py` 仅在临时副本执行，原始输出单独归档。

## 阻止合并的关键失败

- 无法识别、零候选、无效 JSON、超限、无锚定或未完整确认却生成推荐。
- 预算区间缺端点、非法格式、倒置、模式冲突或标量与 max 不一致未拒绝；预算/天数被静默补值。
- 0 元被误拒、0 元+366 天被误放行、低于 min 被当作失败或静默改价。
- 选择前调用呈现、重复确认重复生成、跨快照/改输入/过期快照被接受、全局修订超过一次。
- 包装价格字段被隐藏而不是拒绝，或三个候选费用被相加；展示文本、配色、话术绕过禁忌和时间复核。
- 服务身份不匹配、mock 未显著标识、失败候选可选、加载/超时/重复点击状态不可见。

## 证据格式

每项记录：命令、开始/结束时间、实际计数、原始输出路径、PASS/FAIL/SKIP、最小复现、文件行号、限制和责任线。失败回开发负责人；QA 不代修业务代码。最终报告待 PM 审查，不合并。
