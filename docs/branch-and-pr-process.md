## 1. 分支模型（现行）

| 分支 | 角色 | 说明 |
| --- | --- | --- |
| `main` | **交付主干** | 评委看到的版本即此。只接受 PR 合并，不直接提交 |
| `release/2026-11-01-submission` | **集成分支** | 多 Agent 共用的工作目录所在分支 |
| `line/<线名>` | **分线分支** | 每条交付线一条，**有真实改动时才创建**；一个分线 = 一个 PR = 一个合并决定 |
| `batch/<批次名>` | 批次分支 | 跨线打包时使用（如"文档收尾"批次）；同样**有真实改动才创建** |

**不使用长期存在的空分支。** 分支必须指向**有内容的提交**。

## 3. PR 合并条件（缺一不可）

1. **交付物已提交**，且报告里给出**真实命令与原始输出**——不接受"应该可以""理论上没问题"。
2. **PM 独立复核通过**（`AGENTS.md`：测试验收独立复核，不能以开发声明代替证据），
   且回归保持绿色（本机探针、单元测试）。
3. **口径诚实**：未做到的一律写"未核实 / 未发生"，不得把设计当已实现。
4. PR 描述写清三件事：**改了什么、证据在哪、还剩什么没做到**。

**不允许"挂着不管"**：每个 PR 最终必须落到 **已合并** 或 **已关闭**（关闭必须写明原因）。

## 4. 分线机制：快照式分线分支（现行，2026-10-31 修订）

**为什么之前看不到分线。** 多个 Agent **共用同一个工作目录**，而"分支"是**工作目录的属性**——
一个目录只能处在一个分支上。因此各线只能把改动堆在集成分支 `release/2026-11-01-submission` 上，
GitHub 上没有分线，也就没有"合不合并"的决定。早期建 8 条 `task/*` 空分支试图凑数，那是**假分线**，已删除。

**现行做法。** PM 用**临时索引文件**把某一线的改动单独写成一个提交，挂到 `line/<线名>` 上。
**全程不切换分支、不碰 `.git/index`、不改工作区**，因此正在写文件的 Agent 完全无感：

```bash
BASE=$(git rev-parse release/2026-11-01-submission)
idx=.git/tmp-idx                      # 临时索引，代替 .git/index
GIT_INDEX_FILE=$idx git read-tree "$BASE"
GIT_INDEX_FILE=$idx git add -A -- <该线的文件路径...>
tree=$(GIT_INDEX_FILE=$idx git write-tree)
commit=$(git commit-tree "$tree" -p "$BASE" -m "<该线说明>")
git update-ref refs/heads/line/<线名> "$commit"   # 不动 HEAD
```

再 `push` 该分支、以集成分支为基开 PR。各线的**文件集合互不重叠**，所以合并顺序不影响结果。
脚本：`.tmp/make-line-branches.sh`（gitignored，可重跑以刷新快照）。

**这能成立与不能成立什么（如实说明，不夸大）**

- ✅ **成立**：每条线一个**有内容的分支** + 一个**可评审的 PR**；可以合并，也可以不合并并写明原因；
  每条线的评审范围与历史清晰；分支可随该线推进反复刷新。
- ❌ **不成立**：这不是"各自独立开发再合并"那种分线。**同一个文件仍然只能存在一个版本**——
  两条线无法同时持有同一文件的不同内容（这正是文件归属规则禁止路径重叠的原因）。
- **要真正做到独立开发**，需要给每条线一个 `git worktree` 独立目录。当前各线改动**大量处于未提交状态**，
  新建 worktree 会得到一个**过时的基线**（拿不到别线的在途成果），因此暂不启用；
  待各线快照入库、工作区趋近干净后再评估。

## 5. 给各 Agent 的强制约束（必须写进每个 Agent 的提示词）

```
⚠️ 禁止任何 git 分支操作：不要执行 git checkout / switch / branch / merge / rebase / push。
多个 Agent 共用同一个工作目录，切换分支会让其他 Agent 正在写的文件消失。
你只需把改动留在工作区；确需提交时只许 `git add <你自己的文件>` + `git commit`，
提交、开分线分支、开 PR、合并一律由 PM 统一处理。
（PM 会用"临时索引 + commit-tree"的快照方式把你的在途改动放进 `line/<线名>` 分支，
 你不需要、也不允许自己去切分支。）
```
