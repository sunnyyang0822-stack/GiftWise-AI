## 2. API 成本：供应商、单价、预算与实付

### 实际通道与限制

【实测·源码/历史账本核对】当前主链是 Node 服务端直连 OpenAI 兼容 `/chat/completions`；Dify 是显式对照模式，不能把早期 Dify 13 次调用、38,326 tokens 加进当前预算。实际历史账本 `evidence/runtime-c/evidence/model-ledger.jsonl` 记载 host=`api.modelverse.cn`、model=`deepseek-v4.1-flash-1017`。模型与地址由服务端配置，源码没有固定默认文本型号；因此该型号是已有项目调用证据，**不是对未读取的当前秘密配置或未来部署配置的保证**。没有读取实际 .env 或密钥值。

【实测·源码核对】默认文本输出上限 16,384 tokens；解析 8,192；视觉方向润色 4,096。HTTP 输入体上限 262,144 bytes；工具结果默认有界到 256,000 字符，不能把字符数直接当 tokens。官方目录该型号 `MaxModelLen=1024000`；这不表示客户端有等大的输入 token 硬闸，也不表示每任务费用有对应硬上限。

【推算】公式（单位元）：

`C_text = ((I-H)×P_input + H×P_cache + O×P_output) / 1,000,000`

`C_image = 成功生成张数 × 0.25`；`C_task = Σ各次物理执行的文本费用 + C_image + C_extra`。

I 为包含缓存的 prompt_tokens，H 为其中 cached_tokens，O 为 completion_tokens。本文缓存价未知时令 P_cache=P_input=2；**不要先算完整 I，再额外加 H**。reasoning 已包含在 completion 中，不再加一次；total_tokens 只作校对，不与 I/O 再相加。每轮工具返回会进入后续上下文，后续请求的 token 是新的计费输入；已有 usage 已含这些输入，不能再以工具结果长度重复加费。`C_extra` 包括潜在检索服务、带宽、主机、存储等，本表未纳入，其实付未测；本版公开 HTTP 检索没有已核实的按次商业搜索价，不臆造收费或全站零成本。

### 调用数不能固定为 4+1

【实测·源码核对】解析、排除识别可无调用或命中缓存；排除澄清成功接续最多 10 轮，每轮仍可能调模型。推荐默认最多 2 轮工具（参数硬钳 4），单批最多 32 tool calls、执行并发最多 3、实际查询最多 6；模型每轮仍收费。另有最多一次格式重试、一次依据确认，推荐逻辑调用常见 1–3 次；按默认分支穷举保守取 1–5 次（允许 4 轮工具时 1–7 次）。业务推荐修订另 1 次，不带工具或新的格式重试循环。

【实测·源码核对】视觉方向润色 0–1 次；每个新选择的指南 1–2 次文本调用（含格式重试）。live 指南不合格时如实失败，**没有再调用一次真实呈现业务修订的实现**，不能照旧注释加费。全局一次业务修订仍由独立规则与服务端计数保护。用户可依次选择不同合格候选，同 run 最多涉及 3 份新指南和 3 张新图片；同候选重放、只读 GET 复用原任务。

【实测·源码核对】文本默认 maxRetries=2，即每逻辑调用至多 3 次 HTTP 尝试；transport 对重试数硬钳 3，即配置极限为 4 次尝试，不能误写“硬上限 3 次调用”。2xx 结构错误不在 transport 重试；业务层格式重试独立。账本通常只记录整次 invoke 的最终 usage 与 attempts，不能把 attempts>1 的最终 usage 当成所有尝试总量。

【推算】只限定一次解析、初始识别+10次成功澄清、一次推荐、一次选择时，默认分支保守计数可达 `2+22+5+1+1+2=33` 次逻辑文本调用，再乘各自传输尝试。此数不是任意用户交互的全局费用封顶：重新分析/新 run/换选仍可增加；LLM_CALL_BUDGET 默认未设为 null，设空串会成为 0。已配置预算也是落盘行数检查，既不按物理尝试收费锁定，也不是多进程原子额度锁。

## 3. 端到端延迟

【推算·指标定义】T选：从提交有效需求到三个通过独立检查的方案在 UI 可选；T文：用户明确选择后到通过检查的指南文字渲染可读；T图：同次选择到最终图片状态 ready 且浏览器可显示；T错：从供应商/服务失败可知到中文反馈可见。人工阅读、确认、澄清回答、比较选择等待另列 H，不算模型处理。完整用户墙钟是机器关键路径加 H，不能以异步 POST 200 当 T图，也不能把独立请求按时间相邻拼会话。

【实测·源码核对】解析/排除发生在相应输入路径；推荐等候初始检索，工具回调按每轮并行分支最长耗时进入关键路径，再经过推荐输出、独立检查/必要修订、视觉方向后返回。选择后指南调用→独立复核→仅建立图片任务→文字返回；图片在后台执行，`media_wait.waited=false, timeout_ms=0`。`GIFTWISE_PRESENTATION_WAIT_MS` 虽仍读取默认 30000，当前 pipeline 已不引用；旧同步等图优化不能再列为未来尚未实现。

【推算】生产阶段预算可用 `T选≈T解析+T排除+Σ轮次(模型+max(并行工具))+T检查/修订+T方向+T网络/UI`，以实际触发和缓存扣除分支；H 单列。T文包括指南与复核、落盘任务建立、网络/UI；T图还含后台生成、写盘、轮询与显示，文字返回与图像执行有重叠，不盲目再加整个 T文。推荐图已停，不能恢复电商采集或预生成包装图换延迟。
