# 验收标准

更新时间：2026-10-30（北京时间）。状态：产品对齐完成，契约决定已记录；缺口 G-1…G-4 待补（见 `docs/pm-reviews/stage-2-acceptance-checklist-2026-10-30.md`）。

## P0 功能验收

- [ ] 输入包含关系、熟悉程度、场合、预算、准备时间、兴趣／风格、禁忌和补充说明。
- [ ] 预算支持预设区间、自定义金额，并在提交前确认明确上限。
- [ ] 时间支持区间选择，并在提交前确认最终可用天数。
- [ ] 首版只接受 CNY；不得静默换汇或补默认值。
- [ ] 恋人和追求对象是两个独立关系值（`partner`／`pursuit`）、独立提示和独立输出文案。
- [ ] **同事完全移出产品场景**：不出现在界面、导航、演示脚本和验收案例中（仅技术回归夹具保留）。
- [ ] 每个兴趣可单独标记可信度（`confirmed`/`inferred`）；界面“未知”状态不生成用户事实，提交为 `interests: []`。
- [ ] 无兴趣时输出低压力、实用、可替代或可自主选择的方向，避免强烈浪漫、尺寸敏感、气味敏感和明显个性化物品。
- [ ] 阶段一输出恰好三个不同方案，区分事实、推断、未知。
- [ ] 每个方案显示全量估算费用、币种、准备时间、理由和检查结果。
- [ ] 规则检查独立于模型；失败项不可选。
- [ ] 自动业务修订跨两个阶段总计最多一次，并在修订后重新检查。
- [ ] 用户未选择前，不调用包装／贺卡／赠送设计阶段。
- [ ] 选择后严格按“风格配色→包装→贺卡及花等装饰→赠送时机和话术”呈现。
- [ ] 呈现阶段复核礼物、包装、贺卡、装饰和配送的总费用、准备时间及禁忌。
- [ ] 无法通过时显示中文失败原因，不伪装为完成。
- [ ] 前端不能通过篡改 `passed`、候选内容或修订次数获得选择权限。

## 场景验收

- [ ] 恋人生日：文案可亲密但不承诺对方反应。
- [ ] 追求对象节日：文案低压力，不默认双方已恋爱或互有好感。
- [ ] 朋友感谢：未知兴趣时仍能给出低风险方向。
- [ ] 明确禁忌：类别和字面禁忌都被拦截。
- [ ] 超预算：边界金额通过，超过一分钱失败。
- [ ] 准备时间边界：等于可用天数通过，超过一天失败。
- [ ] 无兴趣：不凭职业、性别或年龄编造事实。
- [ ] 未选择：不提前生成任何详细包装方案。
- [ ] 选择失败项、旧版本或伪造候选：拒绝并说明原因。
- [ ] 模型 JSON 损坏、Code 失败或超时：显示暂不可用，不标为通过。

## 证据要求

验收记录必须包含实际命令、时间、Git SHA、输入版本、预期与实际结果、错误代码、阶段、修订次数、模型调用次数、耗时和限制。未实测的 Dify、前端、部署、价格、库存、物流和 60 秒目标保持“待验证”。
