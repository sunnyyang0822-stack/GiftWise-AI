### 3.2 字段语义与代码出处（`web/server/localdb-real/catalog.mjs:21-54,179`）

| 字段 | 语义 |
|---|---|
| `pid` | 处理**这次请求**的进程号 |
| `started_at` | 该模块加载（≈进程启动）时刻 |
| `running_code_revision` | **本进程加载时**算出的代码版本：`sha256(catalog.mjs + db.mjs + schema.mjs)` 前 16 位 |
| `on_disk_code_revision` | **处理本次请求时**对**同三个文件**重新计算的结果 |
| `stale_process` | `onDisk !== running` ⇒ **这是一个旧进程** |

⇒ **`stale_process=true` 就是「这份响应不可信，必须重启」的机器判据**（代码注释原文：「`stale_process: true` 表示**这是一个旧进程，必须重启**，它返回的数据不可信」）。

### 3.3 ⚠️ 只有该路由带 `process`；`/api/config` **不带**【实测】

```console
$ curl -s http://127.0.0.1:8903/api/config | (取顶层键)
top-level keys: ['mode','dify_configured','dify_published_verified','llm_configured','services',
                 'pursuit_contract_ready','pursuit_notice','intake_parse','notices','unknown_interests_hint',
                 'labels','ranges','budget_slider','budget_modes','limits','client_timeout_ms','attestation']
has process?      False

$ curl -s "http://127.0.0.1:8903/api/catalog?limit=1"
```

**两个块不是一回事，必须分开读**：`/api/catalog` 有 `process` 没有 `attestation`；`/api/config`、`/healthz` 有 `attestation` 没有 `process`（出处 `web/server/server.mjs:364,368,375-379`）。

### 3.4 ⚠️ `stale_process` 才是磁盘比对；`attestation.stale` **不是**新鲜度判断

```console
$ curl -s http://127.0.0.1:8903/healthz
{"status":"ok","mode":"llm","runs":0,"attestation":{"pid":51020,"code_revision":"14ada98eaf5d55e1",
 "started_at":"2026-10-31T15:29:08.612Z","uptime_ms":1074497,
```

`web/server/attest.mjs:76-78` 的实现原文：`const stale = Boolean(declared) && declared !== CODE_REVISION;` ⇒ **只有调用方主动声明了 `client_code_revision`／`x-giftwise-code-revision` 且与本进程不一致时**，`attestation.stale` 才为 `true`；**没声明时恒为 `false`**。⇒ 拿 `attestation.stale:false` 当「我是最新代码」的自述**不成立**。
（独立验收的对照证据：`gw-live/docs/architecture/独立验收-汇总-2026-11-01.md:31-37` 记录两个**都自报 `stale:false`** 的进程——其中一个 `code_revision` 已过时、另一个也不是磁盘代码。）

**两个哈希口径不同，不要互相比**：`attestation.code_revision` 覆盖 `web/server/**`；`process.running_code_revision` 只覆盖 `catalog.mjs + db.mjs + schema.mjs`。本机实测两者分别是 `14ada98eaf5d55e1` 与 `1354b5a7dd7d5b36`，**这是正常的，不是不一致**。
